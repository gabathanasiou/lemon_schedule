## Free table, cells & cell references

- **Free table** (`block.custom` + `block.customRows`, roadmap 10/188/189; `reports/CustomTable.tsx`): literal rows × columns for free-write tables (transportation plans), rendered with `.report-table-cols`/`.rm-row` so the measured paginator splits it between rows. `ReportTableColumn.label` is the header; every cell is rich text and may carry `{{field}}` / lookup tokens. In the designer (`hint` + `onPatchBlock` — dropping that pass-through silently discards every cell edit) the table edits ITSELF, gated by **Fields/Values mode** (roadmap 203): **Fields** = live cells (headers type in place); **Values** = resolved static cells until an entry gesture makes the WHOLE table live and focuses the clicked cell with the caret at the END (the InlineTextBlock contract): double-click / tap-again on cell CONTENTS from any state, a SINGLE click on a cell once the card is selected, or RIGHT-CLICK on a cell (roadmap 219 — enters editing at that cell and opens the cell context menu). Entry records the FIRST click's cell at pointerdown (selecting the card inserts the in-flow resize strip, shifting the table before the second click, and empty rows are only a few px tall — `cellFromEvent`/`pointerCellRef` in `ReportDesignerCanvas.tsx`). Clicking the card itself (padding/header) never ENTERS editing — it selects the block, reveals the resize chrome, and while editing it EXITS (`editingId` cleared). **Any re-render must keep the static DOM stable**: an inline `dangerouslySetInnerHTML={{ __html }}` object changes identity every render and React's commitUpdate compares by reference — so every canvas re-render (selection, blur, typing elsewhere) re-parsed and REPLACED the text/cell DOM, detaching the node under the cursor between mousedown and mouseup so the browser swallowed the click/dblclick (the "block won't select / double-click does nothing" class of bugs). `htmlProp()` (`src/lib/richText.ts`) caches the prop by HTML string so unchanged content keeps one identity; live-cell drag suppression (`cellDragBlockId`) is ALSO gated to Fields/entry so Values-static pointerdown stays render-free. The ⠿ grip drag-reorders columns (`useTableColumnReorder.ts`, shared with collection tables — insert/duplicate/delete row & column actions live in the cell chrome + context menu; the old hover **+/×** controls sit behind `SHOW_FLOATING_STRUCTURE_CONTROLS` in `CustomTableBands.tsx`), and a **selection-gated row tab on the right edge** (same tab as the column strip, driven by shared `useColumnResize` vertical mode) sets `ReportCustomRow.height` (px min-height, honored in preview/print; double-click resets). Column structure goes through `insertTableColumnAt`/`removeTableColumnAt`/`moveTableColumn`; `mapTableColumns` remaps `customRows[].cells` by column id so values follow their column. Preview/print resolve tokens to static HTML. The column-resize strip (`ColumnResizeStrip`, selection-gated) renders inside `CustomTable` directly above the table (stem ends flush at the table top); its tab, every cell-border segment of that boundary and the drag share ONE active state — hovering or dragging any affordance lights the full vertical line and tab together. The row tab pairs the same way with the row's full-width border hint. **The border strips (`.report-ct-colborder`/`.report-ct-rowborder`) are pure highlight overlays — `pointer-events:none`, never click targets** (direct border grabbing swallowed cell clicks); resize lives on the selection-gated strip tab + row tab. The row boundary segments cover every column whose cell does NOT continue into the next row, so a vertical merge's interior has no line while its BOTTOM edge still highlights (the merged-cells gap in the old skip logic). Values-static cells ALSO resolve with `showUnresolved` (designer only): an empty-valued token renders as a chip, not a blank cell — a REFERENCE (lookup, or a cellref pair) shows an error-red `✕ <ref> | <attribute>` chip (hover = the kit tooltip look via the shared `DelegatedTooltip` host keyed on `data-ui-tooltip`), a plain field a group-color chip with the field's LABEL (never the raw `{{token}}`); preview/print never pass `showUnresolved` and stay blank. **The resize affordances (strip + row handles) are available whenever the card is selected — Values included** (`resizable` = designer && (editable || selected)); only CELL EDITING is mode-gated (`editable` = designer && (fields || table entered)). Collection tables keep their canvas-rendered `TableResizeBar`.
  - **Cells (roadmap 189)**: click selects a cell (Shift+click extends a rectangular range; the outline is edge-only box shadows), and a click on the block card (outside any cell) clears the range so the table's block chrome returns. `reports/TableCellChrome.tsx` floats the selection chrome (label + merge/unmerge/reset + the shared format body `reports/CustomCellControls.tsx`: `reports/RichTextFormatBar.tsx` — inline marks + font/size; a text selection styles the RUN, a collapsed caret patches the focused cell's `cellStyles` default, Mixed shows a multi-cell selection whose overrides differ — plus named paragraph styles and horizontal AND vertical align; the old cell "Insert attribute" picker is gone, attributes come from the editor's own `@` picker); `reports/CustomTableContextMenu.tsx` (kit `ContextMenu`, dark) is the power path (merge/unmerge · insert/duplicate/delete rows · insert/duplicate/delete columns · clear contents — header menu hides row items; deletes act on every covered row/column). **Merges** are `ReportCellMerge { rowId; colId; colSpan; rowSpan }` anchored by stable ids (`rowId: 'header'` = the header band) — `lib/reportTableMerges.ts` is the ONE module (coverage, bands, merge/unmerge, structural remaps): rows render as BANDS (`buildBands` — one `.rm-row` grid per maximal vertical-merge run, cells placed with `gridColumn`/`gridRow` spans, per-row affordances in invisible overlay grid items; the paginator treats a band as one atomic unit, so `rowRange` is a band range), and `mapTableColumns`/the row ops DROP any merge they cut. **Per-cell formatting** lives in `ReportBlock.cellStyles` (keyed `rowId:colId`, pruned at render), module `lib/reportCellStyles.ts`: font family/size, horizontal + vertical align and named paragraph styles (`textStyle` id → `reportTextStyles`); Reset (`resetCellsInBlock`) clears the overrides AND inline formatting. `reports/useCustomTableCells.ts` is the shared cell model (selection + derived merge/style state + every block mutation, incl. `duplicateRow`/`duplicateColumn`) consumed by canvas table + `ReportDesigner`'s docked inspector: the designer owns `selCell` + the focused cell's editor ref, the dock's format toolbar execs against the live canvas editor, floating chromes are gated to `editorMode === 'floating'`, and the table's block chrome hides while a range is selected.
  - **Cell references (roadmap 190)**: type `=` in an EMPTY body cell → the referencing menu (its own kit `ui-menu` dropdown positioned by `useDropdownPosition`, `reports/CustomCellRefMenu.tsx`; `=` is intercepted before the editor (`CustomTable.tsx`) and never stored). Directional entries insert `{{cellref.rel.<dx>.<dy>}}` at the caret, leaving it after the chip so the 121 `.` stage keeps working; "Pick a cell…" enters click-a-cell mode (pointer cursor, button-like cell highlight; a click writes `{{cellref.<rowId>.<colId>}}`, Esc/outside click cancels). `lib/reportTokens.ts` is the resolution seam (extracted from `reportFields.ts`, which re-exports it): **mirror** resolves the target's content in place; a pinned `.<field>` requires the target to reduce to exactly ONE item reference — surrounding label text is fine (`Director: @Bob`), only the token count decides — through nested and PINNED refs, so `@Bob` | `LEFT.phone` | `LEFT.email` chains keep passing the item — and resolves through the lookup resolver (phone/email stay links); **relative** offsets resolve against the formula cell's CURRENT row/column index (row insert/delete follows the neighbour). Missing/cyclic refs → `#REF!`, non-item pins/unknown fields → `#VALUE!` (`.report-cell-error` red in preview/print; the chip turns red live via the adapter's label+color re-apply); an empty target stays empty. The `.` picker stores the 121 PAIR (reference chip + attribute chip) and `suppressCellRefPairs` prints only the pinned value. Chip labels name the referenced cell (`R1C2`, `LEFT`, `ABOVE`) and the attribute sub-chip shows only the field label (`Phone`); hovering a chip tints the chain's ORIGIN cell (the parent source of the info). Units: `src/lib/__tests__/reportTokens.test.ts`.

## Free-table cell model

- **Free-table cell model**: never derive merge coverage or cell-style keys in a view — `lib/reportTableMerges.ts` (incl. block-level ops) and `lib/reportCellStyles.ts` (the `cellStyles` map + inline-format stripping) are the ONE sources; `reports/useCustomTableCells.ts` wires them to block patches and `CustomTableBands.tsx` only renders what they return.

## Item lookup tokens (roadmap 100, two-stage picker 121)

- **Item lookup tokens (roadmap 100, two-stage picker 121)**: `lookup.<collection>.<field>.<encodedItemKey>` (`composeLookupKey`/`parseLookupKey`, `lib/reportLookup.ts`) references ONE item's attribute anywhere a token resolves (text blocks, free-table cells, headers, Call Sheet zone). **Stage 1**: `@` autocomplete lists ITEMS ONLY (from `buildLookupTokens(project, days)`: days, crew, locations, categories, location types, day types, scenes, every element category; days from `useDaybreakSections`) and inserts the collection's identity field (`lookupIdentityField`: crew→`crewName`, locations→`locationName`, days→`dayLabel`, scenes→`sceneLabel` — the chip reads "Scene 23", elements→`elementName`, …). Element keys carry their category (`elementLookupKey` → `<category>::<matchId>`; split with `splitElementLookupKey`) because names are unique per category only. **Stage 2**: a `.` right after a chip offers that item's OWN attributes via `lookupAttributeFields(allFields, collection)` — `fieldsForScope` for its collection (+ category; a cast element adds cast identity fields) minus the identity field, the document-wide GLOBAL divider (production/project/document resolve from ctx, not the item) and smart fields the item kind can't read (crew/locations/rollup types; roadmap 195); the kit inserts the pick as a SECOND, independent chip — a linked nested bubble (kit `attributeItems` + `TokenMeta.nested`, ui-kit v0.1.86). Either chip can be deleted; attribute chips don't drill further. **Resolution**: `resolveReportTokens`/`resolveReportTokensHtml` run `suppressLookupPairs` first — a lookup token DIRECTLY followed by another of the same collection + item prints the attribute only (the reference is its anchor); a lone reference prints the name, a lone attribute still resolves. A scene reference targets ANY project scene (`reportSceneInfoFor`; off-board scenes print blank day/call-time fields). A DANGLING reference prints `#REF!`, an unknown attribute `#VALUE!` (Excel-style) — never a silent blank; an existing-but-empty value stays blank. `resolveToken` finds the item by its stable key (`reportItemKey` / crew id / element category key) through `resolveCollection`, reads the field from the same registry — looked-up phone/email still render as links, empty values still show the canvas tag. **Contextual resolution (roadmap 195)**: scene-derived attributes resolve through the containing chain's scope (`aux.sceneScope`, the ancestor intersection — `scopeLookupTarget`): `@Props.Element List` in a days repeat prints that day's props (shares `unionSceneFieldParts` with `{{props}}`), an element ref's attached scenes/scene count/pages reduce to its scoped scenes (day-list timeline attributes stay element-wide), a bare ref with no scene scope stays project-wide. Cellref pins (`cellref….<field>`) resolve through the same scope. **Chained navigation (roadmap 196 — LOCKED behind `CHILD_NAVIGATION_ENABLED`, `reportLookup.ts`; unlock = roadmap 215)**: references WALK child collections; the path lives in the token (`lookup.<collection>.<field>.nav:<encoded JSON>`: root item + hops, `LookupPath`/`composeLookupPathKey`/`parseLookupPath`; plain keys always URI-encoded so the literal `nav:` marker can't collide, legacy tokens parse unchanged). The `.` stage after any reference chip also offers its child steps (`referenceOffer` → `navChildItems`): day → scenes, element/cast → scenes, scene → elements, category → elements, crew → categories — `→ First scene` / `→ Last scene` plus specific children by name (query-narrowed, 8 per relation). While locked the picker hides child steps; grammar, scoping and resolution stay live and tested. Picking one inserts a chained reference chip (anchor + chain + attribute run suppresses to the value via `pathExtends` + iterative `suppressLookupPairs`; deleting a chip leaves the rest resolving); the chain chip labels from its resolved item (`lookupReferenceLabel`, the editor's `ctx` prop), and its own `.` offers the child item's attributes + children (deeper chains). Chains resolve against their OWN path ancestors (`chainSceneScope` — intersection of every path item's scenes), never the containing block's `aux.sceneScope`: `@EDITH.Categories.Wardrobe.Element List` prints the wardrobe in EDITH's scenes, not every wardrobe in the project. Cellrefs ride a chain target (a pin reads the FINAL item's attribute); child steps compose as lookup chips only. **Suggestions are context-scoped**: text blocks AND free-table cell editors feed `@` `fieldsForScope(allFields, parentCollection)`, so repeat-dependent fields appear only where they resolve (the full registry stays behind lookup chip labels + the `.` stage); the reference list is capped per collection (8) and total (50) so a bare `@` never dumps the whole project — search narrows before the caps, any item stays reachable. Search matches labels, keys AND group names (`searchReportFields`): typing `document` lists every Document attribute in scope (same in the palette). Reference rows show a short right-side kind (`lookupItemsFor`): crew → role, elements → category, locations → type (fallback "Location"), scenes → "Scene", days → "Prod date", else a plain noun ("Category", "Location type", "Day type"). Hints are searchable too (typing `gaffer` finds that crew member).
