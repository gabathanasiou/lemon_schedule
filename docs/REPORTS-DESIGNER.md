# Reports Designer — Agent Guide

Read this before touching anything in the Reports Designer. It's the orientation
map; deep dives live in the linked specs. The system is deliberately built on
three pillars — block tree, collection resolver, field registry — each with ONE
canonical implementation. Never re-derive them.

## Where it lives

- The **Reports Designer is a sub-tab of the Design tab** (`DesignTab.tsx`, sub-tab `designer: 'Reports Designer'`), NOT the Reports tab. It also has a pop-out slot in `App.tsx`.
- The **Reports tab is a different feature**: hand-built DOODs + Element Breakdown views (`DoodsTab.tsx`, `ElementBreakdownView.tsx`). They are NOT block-based and don't use the designer pipeline.
- Rendering is shared: the same `ReportBlockView` tree renders in designer canvas, `ReportPreview`, and print (`ReportPrint.tsx`). One change renders everywhere.

## The three pillars (canonical — don't re-derive)

1. **Block tree** — `types.ts:301` `ReportBlock` (types: `text | field | repeat | table | columns | ribbon | pageBreak | spacer | callTimes | crewTable`; repeat/table are containers). `ReportDesign` = `blocks/header/footer/page`. All tree ops go through `lib/reportBlocks.ts` helpers (`insertInto`, `listOwnerOf`, `moveIntoChildren`, …) — never hand-roll tree manipulation. New blocks come from `makeReportBlock(type, partial)`. Render-time props: `background`/`border` on text/field blocks (auto text color via relative luminance).

2. **Collection resolver** — `lib/reportData.ts`: `resolveCollection` (base list per collection) + `resolveCollectionItems` (applies category filters, `scopedToParent` Lego intersection, nested context). EVERY repeat/table iterates through it. Never build a parallel item list in a view.
   - Context-passing contract (item/parentCollection/parentCategory/outerItem/scopeFilter/aux): `docs/REPORTS-LEGO-CONTEXT.md` — canonical, read before touching `resolveCollectionItems`/`ReportRepeatView`/`ReportTableView`.
   - `ReportProductionTotals` (shootDays/shootMin/pages/scenes/…) is computed ONCE in `buildReportCtx` from daybreak `SectionInfo` — never recompute day/section math in the designer. `reportData.ts` only derives report-shaped projections on top of the canonical daybreak computation.

3. **Field registry** — `lib/reportFields.ts`: every attribute is a `ReportFieldDef` (`key/label/group/scope/get(ctx, item, aux)`) registered in `getReportFieldDefs(project)`. The palette, token picker, and table pickers all filter by scope (`fieldsForScope`). Views resolve values via `reportFieldValueByKey` — never read raw scene properties in a view. Breakdown attributes (cast, backgroundActors, element/custom categories) are pickable inside day repeaters (`days`/`daysOfCast` scopes) and resolve per-day as the union of that day's scenes' values (`dayBreakdownValue`, `reportFields.ts`), composed with the ancestor `sceneScope` intersection like smart fields. Scene Info/Shooting fields stay scene-only.

## What already exists (check before building anything)

- **Smart fields** (`SMART_FIELDS`, `reportFields.ts:238`): `shootTime`, `breakTime`, `smartPages` — context-aware sums (top level = production totals, day = day total, scene = own value, element/cast/category = Lego-scoped sum over scenes). Plus `smartElementCount`/`smartSceneCount` — contextual **counts** (day → distinct elements/scenes that day, category → scoped to the ancestor chain, element → 1, top level → totals). Counts run over SCHEDULED scenes only (`sceneInfos`); cast counts by ID.
- **Precomputed counts as fields**: per-day `daySceneCount`/`dayTotalPages`; per-element `sceneCount`/`totalPages`/`workDays`/`holdDays`/`travelDays`; per-category `categoryElementCount`/`categorySceneCount`/`categoryOccurrences`; production `totalScenes`/`totalShootDays`/`totalShootTime`/`totalBreakTime`/`schedulePages`.
- **Element collection order (roadmap 143)**: `getElementsFor` sorts cast by **Board ID** (the cast id behind "1. GEORGE") and every other category by **name** (numeric-aware, blank last) via `sortReportElements` (`reportData.ts`) — tables, repeats and `elementCallsOfDay` all agree. `EntityDropdown`/pickers keep their own order; never fork a table-only sort.
- **Day types (roadmap 81)** — the day-type registry (`project.dayTypes`) plugs in "lego-style" without a field per type:
  - Base collection `dayTypes` — the **Day Type Breakdown** rollup (one item per registry type): `dayTypeLabel`/`dayTypeCode` (DOOD letter)/`dayTypeColor`/`dayTypeDayCount`/`dayTypeDays`. `dayCount` counts status **and** card days (events-count-everywhere); **`work` = total shooting days** (Work is the default state, never a stored status). `SKIP_EMPTY_TEST.dayTypes` (`dayCount > 0`, default ON → the automatic "Filters" checkbox).
  - Contextual child `dayTypesOfElement` — inside an element/cast repeat: the day types that element has days in. **Data comes from `ReportElementInfo.typeDayLists`** (the events model — `isElementMarked` over the calendar version's nonShootDates, status OR card, non-production days included, `day: -1`), NOT deriveDood's production-only cells. Shares the `dayTypes` field registry (fieldsForScope maps the child scope onto `dayTypes`).
  - Per-day fields (scope `days`): `dayCode` (the day's DOOD cell letter — status → `W`/`SW`/`WF` work-wins → card letter) + `dayTypeEvents` (EVERY type on a multi-type day, manager order).
  - **Per-type element columns**: dynamically generated `total{Type}Days` + `{Type}DayList` (group `Day Types`, scope `elements`) per **custom attachable type in use** (≥1 statused/carded day in the active calendar version) — defined-but-unused types never clutter the pickers; re-marking a day re-adds them. The day-list variants carry the `dayList` marker so the toolbar day-format dropdown applies (blockControls checks the marker, not the static `DAY_LIST_FIELD_KEYS` set).
- **Day call sheet collections (roadmap 99)**: contextual children of `days`, all resolved in `resolveCollection`:
  - `crewOfDay` — the day's crew (explicit `crewIds` → usual-crew template → full roster) with a resolved `crewCallTime` (per-person override → department precall resolved against the general call). `ReportCrewItem` carries stable `roleKey`/`id` plus `linkedElements`/`linkedCrew` (roadmap 11 explicit links, `lib/crewLinks.ts`).
  - `elementCallsOfDay` — one item per element working the day (cast first, then configured categories), carrying the resolved call chain; dynamic stage columns `call_{stageKey}` come from `getCallTimeSettings` (same settings-driven pattern as the day-type element columns). `ReportElementCallItem`.
  - `departmentCallsOfDay` — one item per crew department on the day; `departmentCallTime` is the precall resolved via `resolveCallExpression` against the day's general call. `ReportDepartmentCallItem`.
  - `locationsOfDay` — the day's master + key + DB-matched scene locations as `ReportLocationInfo` items (scope maps to `locations`, so the whole location/weather field family works).
  - `dayNotes` (scope `days`) prints the day's `daybreakMeta.note`; `dayWarnings` (scope `days`) prints the dangling crew-link warnings (`crewLinkWarningsForReportDay` — a crew person on the day whose linked target isn't). Wired through the collection registry (`reportBlocks.ts` labels/order/validity/contextual/identity) and `fieldsForScope` (`crewOfDay` → `crew`, `elementCallsOfDay`/`departmentCallsOfDay` own scopes, `locationsOfDay` → `locations`).
  - **Crew is rule-bearing (roadmap 11)**: `CrewRole.categories` (resolved by `resolveRoleCategories`) feeds `parentScenesOf`/`ruleBearingAncestor`/`resolveCollectionItems`, so a crew repeat/table scopes by its position's element categories ("only crew in this day"); `linkedCrew` is the element-scope field (crew linked to that element).
- **Day grid blocks (items 111/112)**: `callTimes` (`collection: elementCallsOfDay`) and `crewTable` (`collection: crewOfDay`) are day-scoped LEAF blocks sharing ONE seam: `lib/reportGrids.ts` (the read model — `resolveReportGridGroups` groups the canonical collection per staged category, fixed registry columns, normalized widths) + `reports/ReportGridBlock.tsx` (static: one `.report-table-cols` of `.rm-row`s per category, so the paginator splits between rows) + `production/day/InteractiveGridBlock.tsx` (live: `DayTimesGlide` per category / `CrewTableGlide`, writing `daybreakMeta.elementCalls`/`crewCalls` via `patchDayMeta`). `callTimes.category` unset = All categories (cast-first, one table per staged category present on the day); both palette entries are gated to a `days` repeat (`ReportPalette.blockAvailable`), and in Call Sheet → Edit only TEMPLATE-LEVEL `days`-repeat children become interactive — blocks inside `callSheetEdit` stay static.
- **Document Counter**: `counter` field + block `counterStart` — an iteration INDEX, not a count.
- **There is NO generic sum/aggregate/count attribute on blocks.** If a task asks for one, first check whether the count/sum already exists as a field (above) or as DOOD totals (`lib/nonShootStats.ts` `deriveDood` — the single DOOD engine, reused by report aggregates via `computeElementStats`). If you add aggregation, add it as a field/collection behavior in the registry — not as view logic.

## Extending (recipes)

- **New field**: add a `ReportFieldDef` to the right array in `reportFields.ts` (scope must match the item it reads; `smart` scope = universal contextual). Legacy renames go in `LEGACY_FIELD_ALIASES`.
- **New collection**: add to `ReportCollection` (`types.ts:273`) + a branch in `resolveCollection` (`reportData.ts`) + labels/contextual rules in `reportBlocks.ts` (`contextualCollectionsFor`, `parentCollectionOf`, `scopedCollectionLabel`) + the picker will pick it up from the base collections list in `blockControls.tsx`/`CollectionMenu.tsx`. **Typed parent collections** (categories→elements, locationTypes→locations) plug into `TYPED_PARENT_COLLECTIONS` (`reportBlocks.ts`) — the menus/defaults/table-field-scope pipeline is shared; only the `resolveCollection` branch + ctx data are per-collection. Flat DBs (`locations`) filter by type via `block.category` (CollectionMenu's Locations submenu); they are NON-rule-bearing (`NON_SCOPABLE_COLLECTIONS` — no Lego scoping). Crew is rule-bearing since roadmap 11 (position → categories).
- **Location attributes** (scope `locations` + day contexts): one merged family (`locationName`/`locationAddress`/`locationPhone`/`locationMapLink`… + sunrise/sunset/weather) resolving per-item via `locationsOfItem`/`pickLocation` (`reportData.ts`) — a locations-DB item reads its own entry, a day resolves through the `getReportLocation` seam (item 98: day master → DB-matched scene location → blank). Single-valued fields render the item's FIRST location; `block.locationChoice` (type key, "Show location" picker — visible only when >1 locations resolve) picks another. A location with no coordinates (DB default 0/0) has **no pin**: `hasMapPin` (`reportWeather.ts`) is the one gate — the map block renders nothing outside the designer (the "Add a location…" prompt is a DESIGNER-only hint, so an empty day never prints a near-empty page) and map-link fields fall back to the address, or stay blank when there is neither. Weather needs an in-scope day (item's date, else the nearest day ancestor's date) and is prefetched at design-referenced pins (`designLocationsIn` + `prepareSunWeatherForCtx(ctx, design)`); requests are grouped per Open-Meteo endpoint (forecast 5d past→15d ahead, archive past-only). Dates beyond the horizon are cached as a `too-far` miss and the weather fields render a short **"No forecast yet"** hint instead of a bare dash (an unmaterialized prefetch and fetch errors keep the dash).
- **Flat `locations` tables** filter by `block.category` exactly like the repeat path (`ReportTableView` passes the category for `locations`; `resolveCollection` treats the CollectionMenu's `'props'` display default as "all types").
- **`relative` block** (roadmap 27; relabeled **Advance** in roadmap 10): a mini-repeater over the PARENT repeat's post-scope resolved list (`parentList.slice(idx + offset, idx + offset + count)`). The parent repeat/relative views pass `parentItems` + `itemIndex` down; nested relative blocks inside split repeat items resolve from the parent view's already-scoped list. Renders like a repeat (`.rm-repeat-col`/`.rm-item`) so paginator fragment splitting applies untouched. Palette entry gated to repeat contexts (no current item at top level). The built-in Call Sheet template uses it (`+1`) for the "ADVANCE — NEXT DAY" block.
- **Call Sheet Edit Zone** (`callSheetEdit`, roadmap 10): the per-day editable region of a call-sheet template. In the REPORTS DESIGNER the zone is **locked** — a placeholder you place but can't add children to (`insertInto` descends only into repeat/table/relative); its dashed border renders only in the designer (`hint`), never in preview/print. A day-scoped host supplies `aux.callSheetBlocks` (from `daybreakMeta.callSheets[designId]`) to override the template zone children for one day; the same value threads through `ReportPreview`/`ReportPrint` → `useReportPaginator` → `ReportChunkPage`. Per-day editing lives in the Day Manager's full-surface **Call Sheet → Edit** (D17). For a design shaped `days` repeat → (…, `callSheetEdit`, …) it opens `CallSheetCanvas` — a **single white page** rendering the WHOLE design with the selected day's real data (read-only), with the zone slot hosting the REAL designer canvas (`ReportDesignerCanvas` `bare` embed via `CallSheetZoneDesigner`) — palette + canvas drag & drop, drop zones, floating block chrome, column ops and right-click menus, all scoped to the day's zone list. Other shapes fall back to `ReportDesigner` **zone mode**.
- **Free table** (`block.custom` + `block.customRows`, roadmap 10/188/189; `reports/CustomTable.tsx`): literal rows × columns for free-write tables (transportation plans), rendered with the `.report-table-cols`/`.rm-row` classes so the measured paginator splits it between rows for free. `ReportTableColumn.label` is the header; every cell is rich text and may carry `{{field}}` / lookup tokens. In the designer (`hint` + `onPatchBlock` — dropping that pass-through silently discards every cell edit) the table edits ITSELF: headers type in place, hover **+/×** controls insert/delete rows (left gutter) and columns (inside the hovered header cell, whose input padding reserves the space), the ⠿ grip drag-reorders columns (`useTableColumnReorder.ts`, shared with collection tables), and a **selection-gated row tab on the right edge** (the same tab as the column strip, driven by the shared `useColumnResize`'s vertical mode) sets `ReportCustomRow.height` (px min-height, honored in preview/print; double-click resets). Column structure goes through `insertTableColumnAt`/`removeTableColumnAt`/`moveTableColumn` — `mapTableColumns` remaps `customRows[].cells` by column id so values follow their column. Preview/print resolve the tokens to static HTML. The column-resize strip (`ColumnResizeStrip`, selection-gated) renders inside `CustomTable` directly above the table (stem ends flush at the table top); its tab, every cell-border segment of that boundary and the drag share ONE active state — hovering or dragging any affordance lights the full vertical line and the tab together. The same pairing connects the right-edge row tab and the row's full-width border hint. Mouse users can also drag the cell borders directly (invisible grab strips at the column/row boundaries, no selection needed); touch users keep to the tabs so scroll never fights a resize. Collection tables keep their canvas-rendered `TableResizeBar`.
  - **Cells (roadmap 189)**: click selects a cell (Shift+click extends a rectangular range; the outline is edge-only box shadows), and a click on the block card (outside any cell) clears the range so the table's own block chrome returns. `reports/TableCellChrome.tsx` floats the selection chrome (label + merge/unmerge/reset + the shared format body `reports/CustomCellControls.tsx`: the shared `reports/RichTextFormatBar.tsx` — inline marks + font/size; a text selection styles the RUN, a collapsed caret patches the focused cell's `cellStyles` default, and Mixed shows a multi-cell selection whose overrides differ — plus named paragraph styles and horizontal AND vertical align; the old cell "Insert attribute" picker is gone, attributes come from the editor's own `@` picker); `reports/CustomTableContextMenu.tsx` (kit `ContextMenu`, dark) is the power path (merge/unmerge · insert/delete rows · insert/delete columns · clear contents — header menu hides row items; deletes act on every covered row/column). **Merges** are `ReportCellMerge { rowId; colId; colSpan; rowSpan }` anchored by stable ids (`rowId: 'header'` = the header band) — `lib/reportTableMerges.ts` is the ONE module (coverage, bands, merge/unmerge, structural remaps): rows render as grid BANDS (`buildBands` — one `.rm-row` grid per maximal vertical-merge run, cells placed with `gridColumn`/`gridRow` spans, per-row affordances in invisible overlay grid items; the paginator treats a band as one atomic unit, so `rowRange` is a band range), and `mapTableColumns`/the row ops DROP any merge they cut. **Per-cell formatting** lives in `ReportBlock.cellStyles` (keyed `rowId:colId`, pruned at render) with `lib/reportCellStyles.ts` as its module: font family/size, horizontal + vertical align and named paragraph styles (`textStyle` id → `reportTextStyles`); Reset (`resetCellsInBlock`) clears the overrides AND inline formatting. `reports/useCustomTableCells.ts` is the shared cell model (selection + derived merge/style state + every block mutation) consumed by both the canvas table and `ReportDesigner`'s docked inspector: the designer owns `selCell` + the focused cell's editor ref, the dock's format toolbar execs against the live canvas editor, floating chromes are gated to `editorMode === 'floating'`, and the table's block chrome hides while a range is selected.

- **Free-table cell model**: never derive merge coverage or cell-style keys in a view — `lib/reportTableMerges.ts` (coverage, bands, merge/unmerge, block-level ops, structural remaps) and `lib/reportCellStyles.ts` (the `cellStyles` map + inline-format stripping) are the ONE sources; `reports/useCustomTableCells.ts` wires them to block patches and `CustomTableBands.tsx` only renders what they return.

- **Linked paragraph-style runs (roadmap 193)**: the named-style pick (`TextStyleMenu`) is selection-aware — with a text selection in the focused editor it marks the RUN via the kit's `reportTextStyle` mark (`exec('textStyle', id)`, stored as `<span data-text-style="id">`) and holds a ghost selection while the menu is open; with a collapsed caret it patches the object default (`block.textStyle` / `cellStyles.textStyle`, the existing behavior). `resolveReportTextStyleSpans` (`lib/reportTextStyles.ts`) resolves each marker against `project.reportTextStyles` at render time from `resolveReportTokensHtml`, so editing a style restyles every run in canvas, preview and print; a deleted id renders plain. `reports/ReportTextStyleRules.tsx` emits the same typography as scoped CSS for the canvas editors (the mark stores only the link). Applying a run style clears the range's direct font family/size (the object-level precedent); bold/italic marks stay (direct character formatting wins, Word-like).

## Hard-won gotchas

- `aux.index` is 0-based; `counterStart` (block prop) decides where the Counter field starts.
- Nested `elementsOfCategory` repeats render their same-collection tables **once per category** (summary tables — the `onceTables` special case in `ReportRepeatView`, `ReportBlockView.tsx:273`). Don't "fix" this; it's intentional.
- Table axis: `columns` = attributes as columns (one row per item), `rows` = matrix (attributes as rows). `tableItemCollection`/`tableFieldScope` derive the effective collection/field scope — use them, don't inline.
- Pagination (`useReportPaginator` + `lib/reportPagination.ts`): structural pages split at TOP-LEVEL `pageBreak` blocks (`paginateBlocks` — leading no-op, consecutive → blank pages, trailing dropped); there is no per-item expansion. A `pageBreak` ANYWHERE in the render (repeat/relative children included) is a hard chunk boundary: the block renders an invisible `data-rm-pagebreak` marker, the walker emits a `break` unit and the fill closes the page there — a trailing pageBreak per repeat item gives one page per item naturally. Repeat/relative items DISSOLVE into their children (whole blocks, ribbons by strips, tables by rows with repeated headers, nested repeats recursively — `FragmentPartUnit.itemRange`/`itemParts` carry the path to any depth); items that render nothing produce no pages (a break at a page start is a no-op); unsplittable containers (columns/callSheetEdit) containing a break start on a new page as a whole unit; explicit blank pages survive only from consecutive top-level breaks. Splitting/geometry/budget rules: `docs/REPORT_PRINTING_AND_PAGE_BREAKS.md` §2-3. Design changes → `UPDATE_REPORT_DESIGN` (store `actions/reports.ts`); designs are versioned and trashed like other entities.
- **Per-block item filter (roadmap 100)**: `ReportBlock.itemFilter { field, values }` on repeat/table blocks — `applyItemFilter` (`lib/reportData.ts`) runs beside `filterItemsByScope` in `ReportRepeatView`/`ReportTableView`, so designer, preview and print agree. The block chrome's "Filter rows" control (field picker + values) writes it; a filtered block shows an amber **Filtered** badge in the repeat/table canvas header.
- **Item lookup tokens (roadmap 100, two-stage picker 121)**: `lookup.<collection>.<field>.<encodedItemKey>` (`composeLookupKey`/`parseLookupKey`, `lib/reportFields.ts`) references ONE item's attribute anywhere a token resolves (text blocks, free-table cells, headers, the Call Sheet zone). **Stage 1** — the `@` autocomplete lists ITEMS ONLY (items from `buildLookupTokens(project, days)`: days, crew, locations, categories, location types, day types, scenes, and every element category; days come from `useDaybreakSections`) and inserts the collection's identity field (`lookupIdentityField`: crew→`crewName`, locations→`locationName`, days→`dayLabel`, scenes→`sceneLabel` — the chip reads "Scene 23", elements→`elementName`, …). Element item keys carry their category (`elementLookupKey` → `<category>::<matchId>`; split with `splitElementLookupKey`) because names are unique per category only. **Stage 2** — a `.` typed immediately after a chip answers with that item's attributes via `lookupAttributeFields(allFields, collection)` (the FULL registry scoped to the item; a cast item adds the cast identity fields; the identity field itself is excluded) and the kit inserts the picked field as a SECOND, independent chip rendered as a linked nested bubble (kit `attributeItems` + `TokenMeta.nested`, ui-kit v0.1.86). Either chip can be deleted; attribute chips do not drill further. **Resolution** — `resolveReportTokens`/`resolveReportTokensHtml` run `suppressLookupPairs` first: a lookup token DIRECTLY followed by another lookup token of the same collection + item prints as the attribute only (the reference is its anchor); a lone reference prints the name, a lone attribute still resolves. A scene reference targets ANY project scene (`reportSceneInfoFor` — off-board scenes print with blank day/call-time fields). A DANGLING reference prints `#REF!` and an unknown attribute `#VALUE!` (Excel-style) instead of silently blanking; an existing-but-empty value stays blank. `resolveToken` finds the item by its stable key (`reportItemKey` / crew id / element category key) through `resolveCollection` and reads the field from the same registry — looked-up phone/email still render as links and empty values still show the canvas tag. **Suggestions are context-scoped**: text blocks AND free-table cell editors both feed `@` `fieldsForScope(allFields, parentCollection)`, so repeat-dependent fields only appear where they resolve (the full registry stays behind lookup chip labels + the `.` stage), and the reference list is capped per collection (8) and in total (50) so a bare `@` never dumps the whole project — search narrows before the caps, so any item stays reachable. Search matches labels, keys AND group names (`searchReportFields`), so typing `document` lists every Document attribute in scope (same in the palette). Reference rows show a short right-side kind (`lookupItemsFor`): crew → role, elements → category, locations → type (fallback "Location"), scenes → "Scene", days → "Prod date", everything else a plain noun ("Category", "Location type", "Day type"). Hints are searchable too (typing `gaffer` finds that crew member).
- **Skip-empty filter**: `SKIP_EMPTY_TEST`/`SKIP_EMPTY_LABEL` (`lib/reportData.ts`) — per-collection emptiness tests for typed-parent rollups (categories → `elementCount > 0`, locationTypes → `count > 0`; counts built once in `buildReportCtx`). `resolveCollectionItems` applies it when `skipEmptyCategories !== false` (default ON); the repeat/table "Filters" checkbox renders automatically per registered collection ("Skip types with no locations" etc.). A future database registers its test + item count here and both the filter and the chrome follow — no per-collection code.
- Print scoping: `ReportScopeFilter`/`filterItemsByScope` — repeat views MUST apply it after `resolveCollectionItems` (see `ReportRepeatView`). Scopes cover top-level REPEATS only; TABLES always print all items.
- Empty collections: render `emptyHint` in designer, render nothing in print/preview.
- The canvas editor (`ReportDesignerCanvas.tsx`) uses `elementFromPoint` behind a `pointer-events: none` backdrop for right-click targeting — same pattern as the ribbon context menu.
- The block editor panel (`BlockEditorContent`, `blockControls.tsx`) is ONE component rendered on THREE surfaces — the floating chrome above the block, the top toolbar, and the docked **inspector rail** — any change applies to all three. `panel` layout (via `reportEditorLayout.tsx`: `BlockEditorPanelContext`/`useBlockEditorPanel`, `ContentRow` tall wrapper, `editorRowCls`/`editorFieldCls`) stacks labels above controls, fills fields to the column width and wraps rows; the kit `Seg` takes `stretch` there (full-width equal segments). Sections stack: **Style** and **Padding** side by side (two columns) → **Outline** (background fill + border toggle — `field` blocks only) → **Content**. The shared `reports/RichTextFormatBar.tsx` lives in **Content**: for **text** blocks a text selection styles the RUN (font family/size + inline marks), a collapsed caret patches the block default (`fontFamily`/`fontSize`), and Mixed shows a selection spanning runs — so `StyleControls` keeps whole-block font/size + B/I for **field** blocks only. Palette attributes are `type: 'text'` blocks carrying a `{{field}}` token (never `type: 'field'`), so the text-block controls ARE the attribute-block controls.
- The docked rail (`ReportDesigner.tsx`, editor mode `toolbar`; persisted `lemon_schedule_report_editor_mode` + `lemon_schedule_report_rail {open,width}`) is content-aware: no selection → the palette; a selected block/column → its inspector REPLACES the palette (Deselect/Esc brings the palette back). Collapse to a rail + drag-resize via `usePaneResize` (manager-sidebar pattern). Column selections edit the shared column editors — `reportColumnControls.tsx` (`TableColumnEditorContent`, `ColumnStructureControls`) is the one source the floating `.table-column-chrome`/`.column-chrome` and the docked inspector both render (canvas floating column chromes are gated to `editorMode === 'floating'`).
- **Rows-axis tables (roadmap 186)**: `TableRowsMatrix` renders `block.columns` as matrix ROWS; in the designer **every cell of the row** is selectable exactly like a cell of a columns-mode column (click = select, right-click = menu, blue outline around the whole row — `data-table-col-ci` on every cell). The shared editors switch wording via `TableColumnEditorContent.axis` / `ColumnStructureControls.orientation` / `ReportContextMenu` ("Row N of M", Above/Below, Up/Down, Delete row) and hide the columns-only `skipEmpty` toggle; there is no drag-reorder for rows (move via the chrome/menu).
- DnD edge zones: dropping on a block's left/right edge **wraps** it in a new 2-column block — UNLESS the target's immediate owner is a `columns` block, in which case the drop **adds a new column to that container** (left edge = before the target's column, right edge = after), reusing the gutter's `insertColumnAt`/`moveIntoNewColumn`/`duplicateIntoNewColumn` via the shared `insertNewColumn`/`moveToNewColumn`/`duplicateToNewColumn` handlers in `ReportDesigner.tsx` — never a nested columns block. Blocks nested in a repeat inside a column get no edge zones. Escape deselects the selected block/column; the block chrome has a far-right ✕ deselect button.

## Printing flow (custom reports)

Print NEVER fires directly — every entry point opens `ReportPrintDialog`
(`components/reports/ReportPrintDialog.tsx`) first: designer toolbar Print
(`ReportDesigner.tsx:351`) and File → Print → Custom Reports
(`AppHeader.tsx:135`) both call `setCustomReportPrint(design)` in `App.tsx`.
The dialog calls `onPrint(scopes, printOptions)` → `handleReportPrint`
(`App.tsx:624`) → `ReportPrint` renders through the measured paginator; it
signals `onReady` and only then does `window.print()` fire.

### Dialog invariants (MUST NOT)

1. **Never print without the dialog** — `handleReportPrint(design)` called
   straight from a button was the direct-print bug (main-window DesignTab);
   every entry point goes through `setCustomReportPrint`.
2. **Scopes cover top-level REPEATS only** — `scopeFor` in
   `ReportPrintDialog.tsx` matches `block.type === 'repeat'`; TABLES always
   print all items — never add table controls to the dialog.
3. **Ribbon overrides are print-only** — `RibbonPrintOptions`/`ReportPrintOptions`
   (`reportData.ts:123`) never mutate the `ReportDesign`. Keyed by block id,
   they apply to every ribbon block anywhere in the design (nested in repeats/
   columns/header/footer — `collectRibbonBlocks`).
4. **Ribbon defaults come from the block's own props every time the dialog
   opens** — ribbon settings are never persisted; only `page` persists
   (`lemon_schedule_report_print_page_{projectId}`).
5. **Overrides flow through `ReportRibbonView`'s `overrides` prop**
