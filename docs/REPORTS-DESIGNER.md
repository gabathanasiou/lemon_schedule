# Reports Designer — Agent Guide

Read this before touching anything in the Reports Designer. It's the orientation
map; deep dives live in the linked specs. The system is deliberately built on
three pillars — block tree, collection resolver, field registry — each with ONE
canonical implementation. Never re-derive them.

## Where it lives

- The **Reports Designer is a sub-tab of the Design tab** (`DesignTab.tsx`, sub-tab `designer: 'Reports Designer'`), NOT the Reports tab. It also has a pop-out slot in `App.tsx`.
- The **Reports tab is a different feature**: hand-built DOODs + Element Breakdown views (`DoodsTab.tsx`, `ElementBreakdownView.tsx`). They are NOT block-based and don't use the designer pipeline.
- Rendering is shared: the same `ReportBlockView` tree renders in designer canvas, `ReportPreview`, and print (`ReportPrint.tsx`). One change renders everywhere.

## The three pillars (canonical — don't re-derive)

1. **Block tree** — `types.ts:301` `ReportBlock` (types: `text | field | repeat | table | columns | ribbon | pageBreak | spacer | callTimes | crewTable`; repeat/relative render children — a **table is a leaf**, its `children` never render anywhere). `ReportDesign` = `blocks/header/footer/page`. All tree ops go through `lib/reportBlocks.ts` helpers (`insertInto`, `listOwnerOf`, `moveIntoChildren`, …) — never hand-roll tree manipulation. New blocks come from `makeReportBlock(type, partial)`. Render-time props: `background`/`border` on text/field blocks (auto text color via relative luminance).

2. **Collection resolver** — `lib/reportData.ts`: `resolveCollection` (base list per collection) + `resolveCollectionItems` (applies category filters, `scopedToParent` Lego intersection, nested context). EVERY repeat/table iterates through it. Never build a parallel item list in a view.
   - Context-passing contract (item/parentCollection/parentCategory/outerItem/scopeFilter/aux): `docs/REPORTS-LEGO-CONTEXT.md` — canonical, read before touching `resolveCollectionItems`/`ReportRepeatView`/`ReportTableView`.
   - `ReportProductionTotals` (shootDays/shootMin/pages/scenes/…) is computed ONCE in `buildReportCtx` from daybreak `SectionInfo` — never recompute day/section math in the designer. `reportData.ts` only derives report-shaped projections on top of the canonical daybreak computation.

3. **Field registry** — `lib/reportFields.ts`: every attribute is a `ReportFieldDef` (`key/label/group/scope/get(ctx, item, aux)`) registered in `getReportFieldDefs(project)`. The palette, token picker, and table pickers all filter by scope (`fieldsForScope`, defined in `lib/reportLookup.ts` and re-exported here); the ONE collection→field-scope map is `fieldScopeFor` (same module) — `fieldsForScope` maps internally (raw callers are safe) and table pickers use `tableFieldScope(block, parent)` = `fieldScopeFor(tableItemCollection(...))` (matrix: `docs/REPORTS-LEGO-CONTEXT.md` §8). Views resolve values via `reportFieldValueByKey` — never read raw scene properties in a view. Breakdown attributes (cast, backgroundActors, element/custom categories) are pickable inside day repeaters (`days`/`daysOfCast` scopes) and resolve per-day as the union of that day's scenes' values (`dayBreakdownValue` → `unionSceneFieldParts`, `reportLookup.ts`), composed with the ancestor `sceneScope` intersection like smart fields. Scene Info/Shooting fields stay scene-only.

## What already exists (check before building anything)

- **Smart fields** (`SMART_FIELDS`, `reportFields.ts:238`): `shootTime`, `breakTime`, `smartPages` — context-aware sums (top level = production totals, day = day total, scene = own value, element/cast/category = Lego-scoped sum over scenes). Plus `smartElementCount`/`smartSceneCount` — contextual **counts** (day → distinct elements/scenes that day, category → scoped to the ancestor chain, element → 1, top level → totals). Counts run over SCHEDULED scenes only (`sceneInfos`); cast counts by ID.
- **Precomputed counts as fields**: per-day `daySceneCount`/`dayTotalPages`; per-element `sceneCount`/`totalPages`/`workDays`/`holdDays`/`travelDays`; per-category `categoryElementCount`/`categorySceneCount`/`categoryOccurrences`; production `totalScenes`/`totalShootDays`/`totalShootTime`/`totalBreakTime`/`schedulePages`.
- **Element collection order (roadmap 143)**: `getElementsFor` sorts cast by **Board ID** (the cast id behind "1. GEORGE") and every other category by **name** (numeric-aware, blank last) via `sortReportElements` (`reportData.ts`) — tables, repeats and `elementCallsOfDay` all agree. `EntityDropdown`/pickers keep their own order; never fork a table-only sort.
- **Day types (roadmap 81)** — the day-type registry (`project.dayTypes`) plugs in "lego-style" without a field per type:
  - Base collection `dayTypes` — the **Day Type Breakdown** rollup (one item per registry type): `dayTypeLabel`/`dayTypeCode` (DOOD letter)/`dayTypeColor`/`dayTypeDayCount`/`dayTypeDays`. `dayCount` counts status **and** card days (events-count-everywhere); **`work` = total shooting days** (Work is the default state, never a stored status). `SKIP_EMPTY_TEST.dayTypes` (`dayCount > 0`, default ON → the automatic "Filters" checkbox).
  - Contextual child `dayTypesOfElement` — inside an element/cast repeat: the day types that element has days in. **Data comes from `ReportElementInfo.typeDayLists`** (the events model — `isElementMarked` over the calendar version's nonShootDates, status OR card, non-production days included, `day: -1`), NOT deriveDood's production-only cells. Shares the `dayTypes` field registry (fieldsForScope maps the child scope onto `dayTypes`).
  - Per-day fields (scope `days`): `dayCode` (the day's DOOD cell letter — status → `W`/`SW`/`WF` work-wins → card letter) + `dayTypeEvents` (EVERY type on a multi-type day, manager order).
  - **Per-type element columns**: dynamically generated `total{Type}Days` + `{Type}DayList` (group `Day Types`, scope `elements`) per **custom attachable type in use** (≥1 statused/carded day in the active calendar version) — defined-but-unused types never clutter the pickers; re-marking a day re-adds them. The day-list variants carry the `dayList` marker so the toolbar day-format dropdown applies (blockControls checks the marker, not the static `DAY_LIST_FIELD_KEYS` set).
- **Day call sheet collections (roadmap 99)**: contextual children of `days`, all resolved in `resolveCollection`:
  - `crewOfDay` — the day's crew (explicit `crewIds` → usual-crew template → full roster) with a resolved `crewCallTime` (per-person override → department precall resolved against the general call). `ReportCrewItem` carries stable `roleKey`/`id` plus `linkedElements`/`linkedCrew` (roadmap 11 explicit links, `lib/crewLinks.ts`).
  - `elementCallsOfDay` — one item per element working the day (cast first, then configured categories), carrying the resolved call chain; dynamic stage columns `call_{stageKey}` come from `getCallTimeSettings` (same settings-driven pattern as the day-type element columns). `ReportElementCallItem`.
  - `departmentCallsOfDay` — one item per crew department on the day; `departmentCallTime` is the precall resolved via `resolveCallExpression` against the day's general call. `ReportDepartmentCallItem`.
  - `locationsOfDay` — the day's master + key + DB-matched scene locations as `ReportLocationInfo` items (scope maps to `locations`, so the whole location/weather field family works).
  - `dayNotes` (scope `days`) prints the day's `daybreakMeta.note`; `dayWarnings` (scope `days`) prints the dangling crew-link warnings (`crewLinkWarningsForReportDay` — a crew person on the day whose linked target isn't). Wired through the collection registry (`reportBlocks.ts` labels/order/validity/contextual/identity) and `fieldsForScope` (`crewOfDay` → `crew`, `elementCallsOfDay`/`departmentCallsOfDay` own scopes, `locationsOfDay` → `locations`).
  - **Crew is rule-bearing (roadmap 11)**: `CrewRole.categories` (resolved by `resolveRoleCategories`) feeds `parentScenesOf`/`ruleBearingAncestor`/`resolveCollectionItems`, so a crew repeat/table scopes by its position's element categories ("only crew in this day"); `linkedCrew` is the element-scope field (crew linked to that element).
- **Day grid blocks (items 111/112)**: `callTimes` (`collection: elementCallsOfDay`) and `crewTable` (`collection: crewOfDay`) are day-scoped LEAF blocks sharing ONE seam: `lib/reportGrids.ts` (the read model — `resolveReportGridGroups` groups the canonical collection per staged category, fixed registry columns, normalized widths) + `reports/ReportGridBlock.tsx` (static: one `.report-table-cols` of `.rm-row`s per category, so the paginator splits between rows) + `production/day/InteractiveGridBlock.tsx` (live: `DayTimesGlide` per category / `CrewTableGlide`, writing `daybreakMeta.elementCalls`/`crewCalls` via `patchDayMeta`). `callTimes.category` unset = All categories (cast-first, one table per staged category present on the day); both palette entries are gated to a `days` repeat (`ReportPalette.blockAvailable`), and in Call Sheet → Edit only TEMPLATE-LEVEL `days`-repeat children become interactive — blocks inside `callSheetEdit` stay static.
- **Block title (roadmap 140)**: `showTitle` / `titleRepeat` / `titleBlock` on `table` / `callTimes` / `crewTable` / `repeat` (heading ABOVE) and `image` / `map` (caption BELOW) — gated by `supportsTitle`/`titleRepeatable` (`lib/reportBlocks.ts`; captions never split, so no repeat toggle for them). The title IS a real text block, seeded centered + bold at 12pt with V-padding 10 from `reportTitleAutoLabel` (collection label for tables, "Call Times"/"Crew Table" for grids, the repeat's collection heading; captions start blank). It renders through the ONE text renderer `reports/TextBlockView.tsx`, and in the DESIGNER it is ALWAYS LIVE (a title reads as an input: click = caret, drag = text selection; `titleDragBlockId` suppresses ALL cards' native drag for the gesture — `draggable` gates + `onDragStart` — so an enclosing repeat can't hijack it; repeat cards render the title explicitly in `ReportDesignerCanvas.tsx` because they bypass `ReportBlockView`). **Designer-only edit box**: the `.report-block-title` wrapper wears `.report-title-input` when `hint` (`src/index.css` — the kit input language on the white page); preview/print never get it. The chrome's Title section (`reports/blockControls.tsx`) shows Show title (+ Repeat on each page where splittable) + the SAME Format/Style body as text blocks (`TextContentControls`, shared) + Padding, bound to the title's editor channel. Every table-shaped card carries its little header in the designer (tables `Table: …`, grids `Call Times`/`Crew Table`, text `Text`). Pagination: the title's height FOLDS into the block's first content unit (`titleOn` — `flattenTable`/`flattenRepeatContent`) so the page budget counts it and it can never split onto its own fragment; the fragment holding that unit renders it (`BodyChunk`/`FragmentPartUnit.showTitle`; for a repeat the block's first unit, for a table the header/row 0), continuation fragments only when `titleRepeat` (height reserved via row `pageStartExtra`).
- **Document Counter**: `counter` field + block `counterStart` — an iteration INDEX, not a count.
- **There is NO generic sum/aggregate/count attribute on blocks.** If a task asks for one, first check whether the count/sum already exists as a field (above) or as DOOD totals (`lib/nonShootStats.ts` `deriveDood` — the single DOOD engine, reused by report aggregates via `computeElementStats`). If you add aggregation, add it as a field/collection behavior in the registry — not as view logic.

## Extending (recipes)

- **New field**: add a `ReportFieldDef` to the right array in `reportFields.ts` (scope must match the item it reads; `smart` scope = universal contextual). Legacy renames go in `LEGACY_FIELD_ALIASES`.
- **New collection**: add to `ReportCollection` (`types.ts:273`) + a branch in `resolveCollection` (`reportData.ts`) + labels/contextual rules in `reportBlocks.ts` (`contextualCollectionsFor`, `parentCollectionOf`, `scopedCollectionLabel`) + the picker will pick it up from the base collections list in `blockControls.tsx`/`CollectionMenu.tsx`. **Typed parent collections** (categories→elements, locationTypes→locations) plug into `TYPED_PARENT_COLLECTIONS` (`reportBlocks.ts`) — the menus/defaults/table-field-scope pipeline is shared; only the `resolveCollection` branch + ctx data are per-collection. Flat DBs (`locations`) filter by type via `block.category` (CollectionMenu's Locations submenu); they are NON-rule-bearing (`NON_SCOPABLE_COLLECTIONS` — no Lego scoping). Crew is rule-bearing since roadmap 11 (position → categories).
- **Location attributes** (scope `locations` + day contexts): one merged family (`locationName`/`locationAddress`/`locationPhone`/`locationMapLink`… + sunrise/sunset/weather) resolving per-item via `locationsOfItem`/`pickLocation` (`reportData.ts`) — a locations-DB item reads its own entry, a day resolves through the `getReportLocation` seam (item 98: day master → DB-matched scene location → blank). Single-valued fields render the item's FIRST location; `block.locationChoice` (type key, "Show location" picker — visible only when >1 locations resolve) picks another. A location with no coordinates (DB default 0/0) has **no pin**: `hasMapPin` (`reportWeather.ts`) is the one gate — the map block renders nothing outside the designer (the "Add a location…" prompt is a DESIGNER-only hint, so an empty day never prints a near-empty page) and map-link fields fall back to the address, or stay blank when there is neither. Weather needs an in-scope day (item's date, else the nearest day ancestor's date) and is prefetched at design-referenced pins (`designLocationsIn` + `prepareSunWeatherForCtx(ctx, design)`); requests are grouped per Open-Meteo endpoint (forecast 5d past→15d ahead, archive past-only). Dates beyond the horizon are cached as a `too-far` miss and the weather fields render a short **"No forecast yet"** hint instead of a bare dash (an unmaterialized prefetch and fetch errors keep the dash).
- **Flat `locations` tables** filter by `block.category` exactly like the repeat path (`ReportTableView` passes the category for `locations`; `resolveCollection` treats the CollectionMenu's `'props'` display default as "all types").
- **`relative` block** (roadmap 27; relabeled **Advance** in roadmap 10): a mini-repeater over the PARENT repeat's post-scope resolved list (`parentList.slice(idx + offset, idx + offset + count)`). The parent repeat/relative views pass `parentItems` + `itemIndex` down; nested relative blocks inside split repeat items resolve from the parent view's already-scoped list. Renders like a repeat (`.rm-repeat-col`/`.rm-item`) so paginator fragment splitting applies untouched. Palette entry gated to repeat contexts (no current item at top level). The built-in Call Sheet template uses it (`+1`) for the "ADVANCE — NEXT DAY" block.
- **Call Sheet Edit Zone** (`callSheetEdit`, roadmap 10): the per-day editable region of a call-sheet template. In the REPORTS DESIGNER the zone is **locked** — a placeholder you place but can't add children to (`insertInto` descends only into repeat/table/relative); its dashed border renders only in the designer (`hint`), never in preview/print. A day-scoped host supplies `aux.callSheetBlocks` (from `daybreakMeta.callSheets[designId]`) to override the template zone children for one day; the same value threads through `ReportPreview`/`ReportPrint` → `useReportPaginator` → `ReportChunkPage`. **The zone is honored WHEREVER it sits (item 213)**: `findDesignCallSheetZone` (`lib/reportBlocks.ts`) searches the design's body AND header/footer — `DayManagerPage.templateZoneBlocks` and `CallSheetCanvas`'s region walker use it; the walker swaps a direct `callSheetEdit` child to the editable zone slot at its position and dissolves a `days` repeat there to the selected day, while every other header/footer block stays read-only (`readOnlyView`, no patch props — only the zone writes `daybreakMeta.callSheets[designId]`; nested zones render the day's content via `aux.callSheetBlocks` like print). Per-day editing lives in the Day Manager's full-surface **Call Sheet → Edit** (D17). For a design shaped `days` repeat → (…, `callSheetEdit`, …) it opens `CallSheetCanvas` — a **single white page** rendering the WHOLE design with the selected day's real data (read-only), with the zone slot hosting the REAL designer canvas (`ReportDesignerCanvas` `bare` embed via `CallSheetZoneDesigner`) — palette + canvas drag & drop, drop zones, floating block chrome, column ops and right-click menus, all scoped to the day's zone list. EVERY call-sheet design renders through this same page (`callSheetPageBlocks`: the zone-bearing days repeat's children → a plain days repeat's children → the design body): a design without a `callSheetEdit` simply has no editable zone slot — it displays the day page instead of a blank canvas (roadmap 211).
- **Free table** (`block.custom` + `block.customRows`, roadmap 10/188/189; `reports/CustomTable.tsx`): literal rows × columns for free-write tables (transportation plans), rendered with the `.report-table-cols`/`.rm-row` classes so the measured paginator splits it between rows for free. `ReportTableColumn.label` is the header; every cell is rich text and may carry `{{field}}` / lookup tokens. In the designer (`hint` + `onPatchBlock` — dropping that pass-through silently discards every cell edit) the table edits ITSELF, gated by the **Fields/Values mode** (roadmap 203): **Fields** = today's live cells (headers type in place); **Values** = resolved static cells until the entry gesture makes the WHOLE table live and focuses the clicked cell with the caret at the END (the InlineTextBlock contract): a double-click / tap-again on cell CONTENTS from any state, a SINGLE click on a cell once the card is already selected, or a RIGHT-CLICK on a cell (roadmap 219 — enters editing at that cell and opens the cell context menu). Entry records the FIRST click's cell at pointerdown (selecting the card inserts the in-flow resize strip, which shifts the table before the second click, and empty rows are only a few px tall — `cellFromEvent`/`pointerCellRef` in `ReportDesignerCanvas.tsx`). Clicking the card itself (padding/header) never ENTERS editing — it selects the block, reveals the resize chrome, and while editing it EXITS (`editingId` cleared). **Any re-render must keep the static DOM stable**: an inline `dangerouslySetInnerHTML={{ __html }}` object changes identity every render, and React's commitUpdate compares by reference — so every canvas re-render (selection, blur, typing elsewhere) re-parsed and REPLACED the text/cell DOM, detaching the node under the cursor between mousedown and mouseup and making the browser swallow the click/dblclick (the "block won't select / double-click does nothing" class of bugs). `htmlProp()` (`src/lib/richText.ts`) caches the prop by its HTML string so unchanged content keeps one identity; the live-cell drag suppression (`cellDragBlockId`) is ALSO gated to Fields/entry so Values-static pointerdown stays render-free. The ⠿ grip drag-reorders columns (`useTableColumnReorder.ts`, shared with collection tables — insert/duplicate/delete row & column actions live in the cell chrome + context menu; the old hover **+/×** controls are kept behind `SHOW_FLOATING_STRUCTURE_CONTROLS` in `CustomTableBands.tsx`), and a **selection-gated row tab on the right edge** (the same tab as the column strip, driven by the shared `useColumnResize`'s vertical mode) sets `ReportCustomRow.height` (px min-height, honored in preview/print; double-click resets). Column structure goes through `insertTableColumnAt`/`removeTableColumnAt`/`moveTableColumn` — `mapTableColumns` remaps `customRows[].cells` by column id so values follow their column. Preview/print resolve the tokens to static HTML. The column-resize strip (`ColumnResizeStrip`, selection-gated) renders inside `CustomTable` directly above the table (stem ends flush at the table top); its tab, every cell-border segment of that boundary and the drag share ONE active state — hovering or dragging any affordance lights the full vertical line and the tab together. The same pairing connects the right-edge row tab and the row's full-width border hint. **The border strips (`.report-ct-colborder`/`.report-ct-rowborder`) are pure highlight overlays — `pointer-events:none`, never click targets** (direct border grabbing swallowed clicks aimed at the cells); resize lives on the selection-gated strip tab + row tab. The row boundary segments cover every column whose cell does NOT continue into the next row, so a vertical merge's interior has no line while its BOTTOM edge still highlights (the merged-cells gap in the old skip logic). Values-static cells ALSO resolve with `showUnresolved` (designer only): a token whose value is empty renders as a chip instead of a blank cell — a REFERENCE (lookup, or a cellref pair) shows an error-red `✕ <ref> | <attribute>` chip (hover = the kit tooltip look via the shared `DelegatedTooltip` host keyed on `data-ui-tooltip`), a plain field shows a group-color chip with the field's LABEL (never the raw `{{token}}`); preview/print never pass `showUnresolved` and stay blank. **The resize affordances (strip + row handles) are available whenever the card is selected — Values included** (`resizable` = designer && (editable || selected)); only CELL EDITING is mode-gated (`editable` = designer && (fields || table entered)). Collection tables keep their canvas-rendered `TableResizeBar`.
  - **Cells (roadmap 189)**: click selects a cell (Shift+click extends a rectangular range; the outline is edge-only box shadows), and a click on the block card (outside any cell) clears the range so the table's own block chrome returns. `reports/TableCellChrome.tsx` floats the selection chrome (label + merge/unmerge/reset + the shared format body `reports/CustomCellControls.tsx`: the shared `reports/RichTextFormatBar.tsx` — inline marks + font/size; a text selection styles the RUN, a collapsed caret patches the focused cell's `cellStyles` default, and Mixed shows a multi-cell selection whose overrides differ — plus named paragraph styles and horizontal AND vertical align; the old cell "Insert attribute" picker is gone, attributes come from the editor's own `@` picker); `reports/CustomTableContextMenu.tsx` (kit `ContextMenu`, dark) is the power path (merge/unmerge · insert/duplicate/delete rows · insert/duplicate/delete columns · clear contents — header menu hides row items; deletes act on every covered row/column). **Merges** are `ReportCellMerge { rowId; colId; colSpan; rowSpan }` anchored by stable ids (`rowId: 'header'` = the header band) — `lib/reportTableMerges.ts` is the ONE module (coverage, bands, merge/unmerge, structural remaps): rows render as grid BANDS (`buildBands` — one `.rm-row` grid per maximal vertical-merge run, cells placed with `gridColumn`/`gridRow` spans, per-row affordances in invisible overlay grid items; the paginator treats a band as one atomic unit, so `rowRange` is a band range), and `mapTableColumns`/the row ops DROP any merge they cut. **Per-cell formatting** lives in `ReportBlock.cellStyles` (keyed `rowId:colId`, pruned at render) with `lib/reportCellStyles.ts` as its module: font family/size, horizontal + vertical align and named paragraph styles (`textStyle` id → `reportTextStyles`); Reset (`resetCellsInBlock`) clears the overrides AND inline formatting. `reports/useCustomTableCells.ts` is the shared cell model (selection + derived merge/style state + every block mutation, incl. `duplicateRow`/`duplicateColumn`) consumed by both the canvas table and `ReportDesigner`'s docked inspector: the designer owns `selCell` + the focused cell's editor ref, the dock's format toolbar execs against the live canvas editor, floating chromes are gated to `editorMode === 'floating'`, and the table's block chrome hides while a range is selected.
  - **Cell references (roadmap 190)**: type `=` in an EMPTY body cell → the referencing menu (its own kit `ui-menu` dropdown positioned by `useDropdownPosition`, `reports/CustomCellRefMenu.tsx`; the `=` key is intercepted before the editor — `CustomTable.tsx` — and never stored). Directional entries insert `{{cellref.rel.<dx>.<dy>}}` at the caret and leave the caret after the chip so the 121 `.` stage keeps working; "Pick a cell…" enters click-a-cell mode (pointer cursor, button-like cell highlight; a click writes `{{cellref.<rowId>.<colId>}}`, Esc/outside click cancels). `lib/reportTokens.ts` is the resolution seam (extracted from `reportFields.ts`, which re-exports it): **mirror** resolves the target's content in place; a pinned `.<field>` requires the target to reduce to exactly ONE item reference — surrounding label text is fine (`Director: @Bob`), only the token count decides — through nested and PINNED refs, so `@Bob` | `LEFT.phone` | `LEFT.email` chains keep passing the item — and resolves through the lookup resolver (phone/email stay links); **relative** offsets resolve against the formula cell's CURRENT row/column index (row insert/delete follows the neighbour). Missing/cyclic refs → `#REF!`, non-item pins/unknown fields → `#VALUE!` (`.report-cell-error` red in preview/print; the chip turns red live via the adapter's label+color re-apply); an empty target stays empty. The `.` picker stores the 121 PAIR (reference chip + attribute chip) and `suppressCellRefPairs` prints only the pinned value. Chip labels name the referenced cell (`R1C2`, `LEFT`, `ABOVE`) and the attribute sub-chip shows only the field label (`Phone`); hovering a chip tints the chain's ORIGIN cell (the parent source of the info). Units: `src/lib/__tests__/reportTokens.test.ts`.

- **Free-table cell model**: never derive merge coverage or cell-style keys in a view — `lib/reportTableMerges.ts` (coverage, bands, merge/unmerge, block-level ops, structural remaps) and `lib/reportCellStyles.ts` (the `cellStyles` map + inline-format stripping) are the ONE sources; `reports/useCustomTableCells.ts` wires them to block patches and `CustomTableBands.tsx` only renders what they return.

- **Inline text editing (roadmaps 191/203)**: a text block edits INLINE on the canvas — `ReportBlockView`'s text case → `InlineTextBlock` (wrapping the app `RichTextEditor` adapter), focused with the caret at the END (kit `focus('end')`, v0.1.93) once the token NodeViews have rendered. **Fields mode mounts the live chip editor for EVERY text block** (no entry step; the click that lands in one focuses it — `autoFocus` is Values-only), **Values mounts it on double-click / tap-again** (`editingId` in `ReportDesignerCanvas.tsx`; the Values entry wears the `block-text-editing` outline, Fields editors do not). ONE channel owns it: `ReportDesigner` holds `textEditorRef`/`textRtState`/`textChipKey` and threads them to the canvas (which forwards to the editing block and `BlockChrome`) and to `ReportToolbar` (toolbar/dock); `InlineTextBlock` publishes its handle only while its block is SELECTED or FOCUSED (Fields mounts many editors — the dock must target the one being worked on); the chrome's own Content editor is GONE — it renders only the shared `reports/RichTextControls.tsx` body bound to the canvas handle. Leaving the editing block (another selection, background click, Escape) ends editing; in Values the card stays non-draggable while the editor holds focus (drag resumes on blur) so text selection never starts a block drag. Fields keeps the card draggable — the leaf header and padding drag the block, while a `dragstart` inside `.report-text-editor` is cancelled (`ReportDesignerCanvas.tsx`).

- **Fields/Values mode (roadmap 203)**: one global display/edit mode replaces the retired View-menu "Show field keys / Show field values" items. The header's `Fields | Values` kit `Seg` (per-segment `title`, `dense`; sits next to View, works floating + docked) persists `lemon_schedule_report_view_mode` (default **Values**; the old `lemon_schedule_report_keys` key is ignored — no migration). `mode` threads `ReportDesigner` → `ReportDesignerCanvas` → `ReportBlockView`; `showKeys = mode === 'fields'` at that one seam, and the leaf cases branch — text = live editor (Fields) vs resolved + double-click/tap-again entry (Values; an already-selected text block also enters on a single click of its body, deferred ~250ms so the opening click of a double-click still mounts the editor AFTER the second click — otherwise the second click word-selects inside the just-mounted editor); free table = live cells (Fields) vs static resolved + card-selected resize chrome (Values, see the free-table bullet for the entry gestures). **Freshly added text/free-table blocks enter editing with the caret inside** (`autoEditId` set by every insert path and by a table's switch to Free table; the canvas focuses once rendered — free tables get the first cell; Fields mode just focuses the live editor). Preview/print never receive a mode (always values). Text blocks and free tables render the container-style header (`BLOCK_HEADER_CLS`) with a ★ (`src/lib/reportTips.ts` `hasCalculatedContent`; tooltip "Contains calculated values") when their content CALCULATES — text: `{{cellref…}}` or `{{lookup…}}`; free table: cellrefs in cells/header; plain `{{field}}` tokens never star. Attribute (`field`) blocks stay untouched (no header/star).

- **Linked paragraph-style runs (roadmap 193)**: the named-style pick (`TextStyleMenu`) is selection-aware — with a text selection in the focused editor it marks the RUN via the kit's `reportTextStyle` mark (`exec('textStyle', id)`, stored as `<span data-text-style="id">`) and holds a ghost selection while the menu is open; with a collapsed caret it patches the object default (`block.textStyle` / `cellStyles.textStyle`, the existing behavior). `resolveReportTextStyleSpans` (`lib/reportTextStyles.ts`) resolves each marker against `project.reportTextStyles` at render time from `resolveReportTokensHtml`, so editing a style restyles every run in canvas, preview and print; a deleted id renders plain. `reports/ReportTextStyleRules.tsx` emits the same typography as scoped CSS for the canvas editors (the mark stores only the link). Applying a run style clears the range's direct font family/size (the object-level precedent); bold/italic marks stay (direct character formatting wins, Word-like).

## Hard-won gotchas

- `aux.index` is 0-based; `counterStart` (block prop) decides where the Counter field starts.
- Nested `elementsOfCategory` repeats render their same-collection tables **once per category** (summary tables — the `onceTables` special case in `ReportRepeatView`, `ReportBlockView.tsx:273`). Don't "fix" this; it's intentional.
- Table axis: `columns` = attributes as columns (one row per item), `rows` = matrix (attributes as rows). `tableItemCollection`/`tableFieldScope` derive the effective collection/field scope — use them, don't inline.
- Pagination (`useReportPaginator` + `lib/reportPagination.ts`): structural pages split at TOP-LEVEL `pageBreak` blocks (`paginateBlocks` — leading no-op, consecutive → blank pages, trailing dropped); there is no per-item expansion. A `pageBreak` ANYWHERE in the render (repeat/relative children included) is a hard chunk boundary: the block renders an invisible `data-rm-pagebreak` marker, the walker emits a `break` unit and the fill closes the page there — a trailing pageBreak per repeat item gives one page per item naturally. Repeat/relative items DISSOLVE into their children (whole blocks, ribbons by strips, tables by rows with repeated headers, nested repeats recursively — `FragmentPartUnit.itemRange`/`itemParts` carry the path to any depth); items that render nothing produce no pages (a break at a page start is a no-op); unsplittable containers (columns/callSheetEdit) containing a break start on a new page as a whole unit; explicit blank pages survive only from consecutive top-level breaks. Splitting/geometry/budget rules: `docs/REPORT_PRINTING_AND_PAGE_BREAKS.md` §2-3. Design changes → `UPDATE_REPORT_DESIGN` (store `actions/reports.ts`); designs are versioned and trashed like other entities.
- **Per-block item filter (roadmap 100)**: `ReportBlock.itemFilter { field, values }` on repeat/table blocks — `applyItemFilter` (`lib/reportData.ts`) runs beside `filterItemsByScope` in `ReportRepeatView`/`ReportTableView`, so designer, preview and print agree. The block chrome's "Filter rows" control (field picker + values) writes it; a filtered block shows an amber **Filtered** badge in the repeat/table canvas header.
- **Canvas sampling + day picker (roadmaps 197/198)**: a repeat's template preview renders ONE item. Day-scoped designs (`days`/`daysOfCast` repeat or a `callSheetEdit` zone anywhere in the tree — `designIsDayScoped`, `lib/reportBlocks.ts`) get a **View → Report day** submenu in the designer (`ReportDesigner.tsx`; options from `useDayViews` — the Day Manager's source, violation counts included), persisted per design (`lemon_schedule_report_preview_day_{designId}`). Its two states: **All days** (default; stale stored days fall back here) = canvas samples the FIRST production day of the ACTIVE schedule/calendar and Preview/Print render the WHOLE report (roadmap 197 parity — canvas matches preview/print page 1); **Day N** (pinned — shows as `· Day N` on the View trigger) = the day is threaded into `sampleRepeatItem` (`lib/reportSampling.ts`; items come from `ctx.dayInfos`, never re-derived) AND scopes Preview/Print to it (`dayScopeFilter`, `DayReportPreview.tsx`; the print dialog preselects that day's checklist row — the user can re-check others). ONE day-list body serves both surfaces: `DayPickerList` (`src/components/production/day/DayPicker.tsx`) backs the standalone `DayPicker` dropdown (Days page / Call Sheet edit) and this submenu; its optional `allLabel` row + `selectedIndex` with no matching option = All days, picking it calls `onSelect(-1)`. Other collections pick the first item that resolves the most item-scoped tokens (a data-less first row must never show raw `{{tokens}}`). Designer text/free-table editing is mode-gated (roadmap 203 — see the Fields/Values bullet); `showKeys = mode === 'fields'` derives the key view for field blocks, tables and grid blocks at that one seam. Day-scoped breakdown tokens (`{{wardrobe}}` …) resolve the same consolidated, de-duplicated day union in text blocks and cells (`dayBreakdownValue`, `reportTokens.ts`).
- **Item lookup tokens (roadmap 100, two-stage picker 121)**: `lookup.<collection>.<field>.<encodedItemKey>` (`composeLookupKey`/`parseLookupKey`, `lib/reportLookup.ts`) references ONE item's attribute anywhere a token resolves (text blocks, free-table cells, headers, the Call Sheet zone). **Stage 1** — the `@` autocomplete lists ITEMS ONLY (items from `buildLookupTokens(project, days)`: days, crew, locations, categories, location types, day types, scenes, and every element category; days come from `useDaybreakSections`) and inserts the collection's identity field (`lookupIdentityField`: crew→`crewName`, locations→`locationName`, days→`dayLabel`, scenes→`sceneLabel` — the chip reads "Scene 23", elements→`elementName`, …). Element item keys carry their category (`elementLookupKey` → `<category>::<matchId>`; split with `splitElementLookupKey`) because names are unique per category only. **Stage 2** — a `.` typed immediately after a chip answers with that item's OWN attributes via `lookupAttributeFields(allFields, collection)` — `fieldsForScope` for its collection (+ category, a cast element adds the cast identity fields) minus the identity field, the document-wide GLOBAL divider (production/project/document resolve from ctx, not the item) and smart fields where the item kind can't read them (crew/locations/rollup types; roadmap 195) — and the kit inserts the picked field as a SECOND, independent chip rendered as a linked nested bubble (kit `attributeItems` + `TokenMeta.nested`, ui-kit v0.1.86). Either chip can be deleted; attribute chips do not drill further. **Resolution** — `resolveReportTokens`/`resolveReportTokensHtml` run `suppressLookupPairs` first: a lookup token DIRECTLY followed by another lookup token of the same collection + item prints as the attribute only (the reference is its anchor); a lone reference prints the name, a lone attribute still resolves. A scene reference targets ANY project scene (`reportSceneInfoFor` — off-board scenes print with blank day/call-time fields). A DANGLING reference prints `#REF!` and an unknown attribute `#VALUE!` (Excel-style) instead of silently blanking; an existing-but-empty value stays blank. `resolveToken` finds the item by its stable key (`reportItemKey` / crew id / element category key) through `resolveCollection` and reads the field from the same registry — looked-up phone/email still render as links and empty values still show the canvas tag. **Contextual resolution (roadmap 195)**: the target's scene-derived attributes resolve through the containing chain's scope (`aux.sceneScope`, the ancestor intersection — `scopeLookupTarget` in `reportLookup.ts`): `@Props.Element List` inside a days repeat prints that day's props (shares `unionSceneFieldParts` with `{{props}}`), an element ref's attached scenes/scene count/pages reduce to its scoped scenes (day-list timeline attributes stay element-wide), and a bare ref with no scene scope stays project-wide. Cellref pins (`cellref….<field>`) resolve through the same scope. **Chained navigation (roadmap 196 — LOCKED behind `CHILD_NAVIGATION_ENABLED`, `reportLookup.ts`; unlock = roadmap 215)**: a reference can WALK child collections — the path lives inside the token (`lookup.<collection>.<field>.nav:<encoded JSON>`: root item + hops, `LookupPath`/`composeLookupPathKey`/`parseLookupPath`; plain keys are always URI-encoded so the literal `nav:` marker can't collide, and legacy tokens parse unchanged). The `.` stage after any reference chip also offers that item's child steps (`referenceOffer` → `navChildItems`, `reportLookup.ts`): day → scenes, element/cast → scenes, scene → elements, category → elements, crew → categories — `→ First scene` / `→ Last scene` plus the specific children by name (query-narrowed, capped 8 per relation). While locked, the picker hides the child steps; the grammar, scoping and resolution stay live and tested. Picking one inserts a chained reference chip (the anchor + chain + attribute run suppresses to the value via `pathExtends` + the iterative `suppressLookupPairs`; deleting a chip leaves the rest resolving); the chain chip labels live from its resolved item (`lookupReferenceLabel`, the editor's `ctx` prop) and its own `.` offers the child item's attributes + its children (deeper chains). Chains resolve against their OWN path ancestors (`chainSceneScope` — the intersection of every path item's scenes), never the containing block's `aux.sceneScope`: `@EDITH.Categories.Wardrobe.Element List` prints the wardrobe in EDITH's scenes, not every wardrobe in the project. Cellrefs ride a chain target (a pin reads the FINAL item's attribute); child steps themselves compose as lookup chips only. **Suggestions are context-scoped**: text blocks AND free-table cell editors both feed `@` `fieldsForScope(allFields, parentCollection)`, so repeat-dependent fields only appear where they resolve (the full registry stays behind lookup chip labels + the `.` stage), and the reference list is capped per collection (8) and in total (50) so a bare `@` never dumps the whole project — search narrows before the caps, so any item stays reachable. Search matches labels, keys AND group names (`searchReportFields`), so typing `document` lists every Document attribute in scope (same in the palette). Reference rows show a short right-side kind (`lookupItemsFor`): crew → role, elements → category, locations → type (fallback "Location"), scenes → "Scene", days → "Prod date", everything else a plain noun ("Category", "Location type", "Day type"). Hints are searchable too (typing `gaffer` finds that crew member).
- **Skip-empty filter**: `SKIP_EMPTY_TEST`/`SKIP_EMPTY_LABEL` (`lib/reportData.ts`) — per-collection emptiness tests for typed-parent rollups (categories → `elementCount > 0`, locationTypes → `count > 0`; counts built once in `buildReportCtx`). `resolveCollectionItems` applies it when `skipEmptyCategories !== false` (default ON); the repeat/table "Filters" checkbox renders automatically per registered collection ("Skip types with no locations" etc.). A future database registers its test + item count here and both the filter and the chrome follow — no per-collection code.
- Print scoping: `ReportScopeFilter`/`filterItemsByScope` — repeat views MUST apply it after `resolveCollectionItems` (see `ReportRepeatView`). Scopes cover top-level REPEATS only; TABLES always print all items.
- **Context menus (roadmap 219)**: the block/column menu is the kit `ContextMenu` (`reports/ReportContextMenu.tsx`). Pickers are SUBMENUS with the SAME item bodies as the chrome pickers: table column + field block → **Attribute** (`FieldPickerItems`), repeat/table → **Repeat over** / **Table over** (`CollectionMenuItems`) — never a forked list (the collection builders `repeatMenuCollections`/`tableMenuCollections`/`collectionPickPatch`/`selfRepeatDisabledCategories` live in `lib/reportBlocks.ts`). "Add block inside" exists ONLY for `repeat`/`relative`, labelled with the EFFECTIVE scope (`insertScope`: a repeat's items / an Advance's parent repeat). Tables are leaves — `insertInto` never descends into one (an insert aimed at a table lands as its sibling; descending created invisible orphans). Impossible actions are `disabled`, not no-ops: Move row/column at the first/last position, Delete row/column with one left (`canMovePrev`/`canMoveNext`/`canDeleteColumn` — the free-table cell menu's `canDeleteRows`/`canDeleteColumns` precedent). `useTableColumnReorder.startDrag` ignores non-left buttons — a right-click's pointerup used to re-select the column, clear `selId` and unmount the open menu. Image ("Remove image") and map ("Use the day's location" / "Clear pin") quick actions patch through `onPatch`; `callSheetEdit` has no Duplicate (hosts honour only the first zone). Free-table cells own their right-click whenever `designer` (`hint` + `onPatchBlock`) — Values-static also opens the cell menu, entering editing at that cell first (`onEnterTableEdit`).
- Empty collections: render `emptyHint` in designer, render nothing in print/preview.
- The canvas editor (`ReportDesignerCanvas.tsx`) uses `elementFromPoint` behind a `pointer-events: none` backdrop for right-click targeting — same pattern as the ribbon context menu.
- The block editor panel (`BlockEditorContent`, `blockControls.tsx`) is ONE component rendered on the floating chrome above the block and the docked **inspector rail** (the retired top bar is gone) — any change applies to both. **Docked is the DEFAULT** (`lemon_schedule_report_editor_mode`; floating is opt-in and persists) — the surface switch + collapse live IN the chrome header (block/column/cell chromes; block: `trailing`, column: `headerTrailing`, cell: threaded canvas → `CustomTable` → `CustomCellControls`), so the rail has no separate bar (only the palette state shows a one-row header with the actions). **There is no Deselect button** — Esc / clicking the canvas background deselects. `panel` layout (via `reportEditorLayout.tsx`: `BlockEditorPanelContext`/`useBlockEditorPanel`, `ContentRow` tall wrapper, `editorRowCls`/`editorFieldCls`) stacks labels above controls, fills fields to the column width and wraps rows; the kit `Seg` takes `stretch` there (full-width equal segments) and `EditorCheckbox` makes a checkbox a full-width row (pass `flex-1` in an `EditorGroup` for equal halves — Header row / Cell borders read like the Axis Seg). Group headers use the shared `EditorSection` (panel: eyebrow + hairline rule; bar: label-left row) so **Format/Style/Row/Column read as sections** exactly like Padding/Content; `EditorGroup` keeps related controls (mark buttons, alignment trios, label+input pairs, the checkbox pair) as unbreakable clusters when a row wraps, and cluster dividers are kept on every surface — the kit `FormatToolbar` wraps in place (ui-kit v0.1.96) and `ChromeHeader` wraps both its trailing slot and the trailing's own contents (v0.1.98; `StructureControls` stays one cluster). **Nothing clips**: never force `min-w-max` on the rail, and never reserve an empty grid column (a text block has no Style column — Padding gets the full width). Sections stack: **Style** and **Padding** side by side (two columns) → **Outline** (background fill + border toggle — `field` blocks only) → content groups in reading order — repeat/table: **Display** (Mode · Axis · header/borders · day format) → **over** → **Filters** → **Behavior**; text: **Format** → **Style**. The panel skips the outer "Content" eyebrow (each group's own rule is the header — a leading Content rule stacked two hairlines). The rich-text controls are ONE shared body — `reports/RichTextControls.tsx` (Format row = `RichTextFormatBar`; Style row = named `TextStyleMenu` + alignment, plus the vertical-align segment for cells) — consumed by the text case of `BlockEditorContent` and by `CustomCellControls`; for **text** blocks a text selection styles the RUN (font family/size + inline marks), a collapsed caret patches the block default (`fontFamily`/`fontSize`), and Mixed shows a selection spanning runs — so `StyleControls` keeps whole-block font/size + B/I + alignment for **field**/link blocks only. Palette attributes are `type: 'text'` blocks carrying a `{{field}}` token (never `type: 'field'`), so the text-block controls ARE the attribute-block controls — inserted from the editor's own `@` picker (the old separate "Insert attribute…" control is gone, roadmap 205). The Text styles modal (`TextStyleMenu.tsx`) edits one style with the same editor-chrome controls (TB_PICKER selector, B/I toggles, FontMenu, TB_NUM size) and a wrapping paper preview; its `width` prop must be a `max-w-*` class (see DESIGN-LANGUAGE §Modal anatomy — a `w-[…]` silently runs it edge-to-edge).
- The docked rail (`ReportDesigner.tsx`, editor mode `toolbar`; persisted `lemon_schedule_report_editor_mode` + `lemon_schedule_report_rail {open,width}`) is content-aware: no selection → the palette; a selected block/column → its inspector REPLACES the palette (Esc brings the palette back). Collapse to a rail + drag-resize via `usePaneResize` (manager-sidebar pattern). `CollectionMenu`'s panel trigger is `w-full` but its MENU keeps a fixed width class — never pass the trigger's `w-full` as the menu content width (a portaled `w-full` panel opens squished/wrong). - **Rows-axis tables (roadmap 186)**: `TableRowsMatrix` renders `block.columns` as matrix ROWS; in the designer **every cell of the row** is selectable exactly like a cell of a columns-mode column (click = select, right-click = menu, blue outline around the whole row — `data-table-col-ci` on every cell). ## Printing flow (custom reports)

Print NEVER fires directly — every entry point opens `ReportPrintDialog`
(`components/reports/ReportPrintDialog.tsx`) first: designer toolbar Print
(`ReportDesigner.tsx:351`) and File → Print → Custom Reports
(`AppHeader.tsx:135`) both call `setCustomReportPrint(design)` in `App.tsx`.
The dialog calls `onPrint(scopes, printOptions)` → `handleReportPrint`
(`App.tsx:624`) → `ReportPrint` renders through the measured paginator; it
signals `onReady` and only then does `window.print()` fire.

### Dialog invariants (MUST NOT)

1. **Never print without the dialog** — `handleReportPrint(design)` called
   straight from a button was the direct-print bug (main-window DesignTab);
   every entry point goes through `setCustomReportPrint`.
2. **Scopes cover top-level REPEATS only** — `scopeFor` in
   `ReportPrintDialog.tsx` matches `block.type === 'repeat'`; TABLES always
   print all items — never add table controls to the dialog.
3. **Ribbon overrides are print-only** — `RibbonPrintOptions`/`ReportPrintOptions`
   (`reportData.ts:123`) never mutate the `ReportDesign`. Keyed by block id,
   they apply to every ribbon block anywhere in the design (nested in repeats/
   columns/header/footer — `collectRibbonBlocks`).
4. **Ribbon defaults come from the block's own props every time the dialog
   opens** — ribbon settings are never persisted; only `page` persists
   (`lemon_schedule_report_print_page_{projectId}`).
5. **Overrides flow through `ReportRibbonView`'s `overrides` prop**
   (`ReportRibbonView.tsx:544`) and replace the block's flags entirely when
   present. The modal preview is `RibbonDummyPreview` (`ReportRibbonView.tsx:635`)
   — dummy daybreak + strips + note/break rows rendered with the REAL row
   renderers and the override flags, so every toggle is visible.
