# Reports Designer — Agent Guide

Read this before touching anything in the Reports Designer. Orientation map
only; deep dives live in the linked specs. Three pillars — block tree,
collection resolver, field registry — each with ONE canonical implementation.
Never re-derive them.

## Where it lives

- The **Reports Designer is a sub-tab of the Design tab** (`DesignTab.tsx`, sub-tab `designer: 'Reports Designer'`), NOT the Reports tab; pop-out slot in `App.tsx`.
- The **Reports tab is a different feature**: hand-built DOODs + Element Breakdown views (`DoodsTab.tsx`, `ElementBreakdownView.tsx`) — NOT block-based, no designer pipeline.
- Rendering is shared: one `ReportBlockView` tree renders in designer canvas, `ReportPreview`, and print (`ReportPrint.tsx`) — one change renders everywhere.
- **The editing focus is a per-user pref (roadmap 233)** — the "Editing:" picker's design is YOURS (`lemon_schedule_report_active_design`, `useActiveDesignId` in `src/lib/persist.ts`); design CONTENTS stay project state. Picking a design never dispatches `SET_ACTIVE_REPORT` — two collaborators edit different designs without switching each other. Project-level `activeReportId` is only the FALLBACK (older files, never-picked users — ADD/DELETE keep it valid; no UI writes it). Other `activeReportId` consumers: the Day Manager call-sheet pick is its own pref (`lemon_schedule_day_manager` → `callSheetDesignId`, `activeReportId` the last-resort fallback); print flows take an EXPLICIT design (File → Print → Custom Reports lists every design; the designer's Print button prints the design you are editing) — no change needed.

## The three pillars (canonical — don't re-derive)

1. **Block tree** — `types.ts:301` `ReportBlock` (types: `text | field | repeat | table | columns | ribbon | pageBreak | spacer | callTimes | crewTable | precalls`; repeat/relative render children — a **table is a leaf**, its `children` never render anywhere). `ReportDesign` = `blocks/header/footer/page`. All tree ops go through `lib/reportBlocks.ts` helpers (`insertInto`, `listOwnerOf`, `moveIntoChildren`, …) — never hand-roll tree manipulation. New blocks: `makeReportBlock(type, partial)`. Render props: `background`/`border` on text/field blocks (auto text color via relative luminance).

2. **Collection resolver** — `lib/reportData.ts`: `resolveCollection` (base list per collection) + `resolveCollectionItems` (applies category filters, `scopedToParent` Lego intersection, nested context). EVERY repeat/table iterates through it — never build a parallel item list in a view.
   - Context-passing contract (item/parentCollection/parentCategory/outerItem/scopeFilter/aux): `docs/REPORTS-LEGO-CONTEXT.md` — canonical, read before touching `resolveCollectionItems`/`ReportRepeatView`/`ReportTableView`.
   - `ReportProductionTotals` (shootDays/shootMin/pages/scenes/…) is computed ONCE in `buildReportCtx` from daybreak `SectionInfo` — `reportData.ts` only derives report-shaped projections on top of it; never recompute day/section math in the designer.

3. **Field registry** — `lib/reportFields.ts`: every attribute is a `ReportFieldDef` (`key/label/group/scope/get(ctx, item, aux)`) registered in `getReportFieldDefs(project)`. Palette, token picker, table pickers all filter by scope (`fieldsForScope`, defined in `lib/reportLookup.ts`, re-exported here); the ONE collection→field-scope map is `fieldScopeFor` (same module) — `fieldsForScope` maps internally (raw callers are safe); table pickers use `tableFieldScope(block, parent)` = `fieldScopeFor(tableItemCollection(...))` (matrix: `docs/REPORTS-LEGO-CONTEXT.md` §8). Views resolve values via `reportFieldValueByKey` — never read raw scene properties in a view. Breakdown attributes (cast, backgroundActors, element/custom categories) are pickable in day repeaters (`days`/`daysOfCast` scopes) and resolve per-day as the union of that day's scene values (`dayBreakdownValue` → `unionSceneFieldParts`), composed with the ancestor `sceneScope` intersection like smart fields. Scene Info/Shooting fields stay scene-only.

- **There is NO generic sum/aggregate/count attribute on blocks.** If a task asks for one, check whether the count/sum already exists as a field (above) or as DOOD totals (`lib/nonShootStats.ts` `deriveDood` — the single DOOD engine, reused by report aggregates via `computeElementStats`). If you add aggregation, add it as a field/collection behavior in the registry — not as view logic.

## Extending (recipes)

- **New field**: add a `ReportFieldDef` to the right array in `reportFields.ts` (scope must match the item it reads; `smart` scope = universal contextual). Legacy renames go in `LEGACY_FIELD_ALIASES`.
- **New collection**: add to `ReportCollection` (`types.ts:273`) + a branch in `resolveCollection` (`reportData.ts`) + labels/contextual rules in `reportBlocks.ts` (`contextualCollectionsFor`, `parentCollectionOf`, `scopedCollectionLabel`) + the picker picks it up from the base collections list in `blockControls.tsx`/`CollectionMenu.tsx`. **Typed parent collections** (categories→elements, locationTypes→locations) plug into `TYPED_PARENT_COLLECTIONS` (`reportBlocks.ts`) — menus/defaults/table-field-scope pipeline shared; only the `resolveCollection` branch + ctx data are per-collection. Flat DBs (`locations`) filter by type via `block.category` (CollectionMenu's Locations submenu); NON-rule-bearing (`NON_SCOPABLE_COLLECTIONS` — no Lego scoping). Crew is rule-bearing since roadmap 11 (position → categories).
- **Location attributes** (scope `locations` + day contexts): one merged family (`locationName`/`locationAddress`/`locationPhone`/`locationMapLink`… + sunrise/sunset/weather) resolving per-item via `locationsOfItem`/`pickLocation` (`reportData.ts`) — a locations-DB item reads its own entry, a day resolves through the `getReportLocation` seam (item 98: day master → DB-matched scene location → blank). Single-valued fields render the item's FIRST location; `block.locationChoice` (type key, "Show location" picker — visible only when >1 locations resolve) picks another. A location with no coordinates (DB default 0/0) has **no pin**: `hasMapPin` (`reportWeather.ts`) is the one gate — the map block renders nothing outside the designer (the "Add a location…" prompt is a DESIGNER-only hint, so an empty day never prints a near-empty page) and map-link fields fall back to the address, blank when there is neither. Weather needs an in-scope day (item's date, else the nearest day ancestor's date) and is prefetched at design-referenced pins (`designLocationsIn` + `prepareSunWeatherForCtx(ctx, design)`); requests are grouped per Open-Meteo endpoint (forecast 5d past→15d ahead, archive past-only). Dates beyond the horizon are cached as a `too-far` miss; weather fields render a short **"No forecast yet"** hint, not a bare dash (an unmaterialized prefetch and fetch errors keep the dash). Fetched values persist per project in a **device-local store** (roadmap 299, `sunWeatherCache.ts`, `lemon_schedule_weather_v1_<uuid>`): a PAST date is settled — never auto-refetched (the Day Manager's weather chip force-refreshes one day from the archive), today/upcoming refetch after 6 h, failures and "No forecast yet" stay session-only, and reverse-geocode labels persist the same way (a settled pin never re-calls Google). **Manual override** (roadmap 301): the Day Manager's Day Details tick-box writes `daybreakMeta.weatherOverride` (condition, high/low, sunrise/sunset) — project state, so it travels/shares/undoes like every other day field. It wins at render time for the day's OWN resolved location (never a location-table row on another pin or an explicit location pick), blank fields fall back to the fetched value, and it works with no location pin. The chip marks it "Manual" and hides refresh; cached values still warm underneath.
- **Flat `locations` tables** filter by `block.category` exactly like the repeat path (`ReportTableView` passes the category for `locations`; `resolveCollection` treats the CollectionMenu's `'props'` display default as "all types").
- **`relative` block** (roadmap 27; relabeled **Advance** in roadmap 10): a mini-repeater over the PARENT repeat's post-scope resolved list (`parentList.slice(idx + offset, idx + offset + count)`). The parent repeat/relative views pass `parentItems` + `itemIndex` down; nested relative blocks inside split repeat items resolve from the parent view's already-scoped list. Renders like a repeat (`.rm-repeat-col`/`.rm-item`) so paginator fragment splitting applies untouched. Palette entry gated to repeat contexts (no current item at top level). The built-in Call Sheet template uses it (`+1`) for the "ADVANCE — NEXT DAY" block.
- **Call Sheet Edit Zone** (`callSheetEdit`, roadmap 10): the per-day editable region of a call-sheet template. In the REPORTS DESIGNER the zone is **locked** — a placeholder you place but can't add children to (`insertInto` descends only into repeat/table/relative); its dashed border renders only in the designer (`hint`), never preview/print. A day-scoped host supplies `aux.callSheetBlocks` (from `daybreakMeta.callSheets[designId]`) to override the template zone children for one day; it threads through `ReportPreview`/`ReportPrint` → `useReportPaginator` → `ReportChunkPage`. **The zone is honored WHEREVER it sits (item 213)**: `findDesignCallSheetZone` (`lib/reportBlocks.ts`) searches the design's body AND header/footer — `DayManagerPage.templateZoneBlocks` and `CallSheetCanvas`'s region walker use it; the walker swaps a direct `callSheetEdit` child to the editable zone slot at its position and dissolves a `days` repeat there to the selected day, while every other header/footer block stays read-only (`readOnlyView`, no patch props — only the zone writes `daybreakMeta.callSheets[designId]`; nested zones render the day's content via `aux.callSheetBlocks` like print). Per-day editing lives in the Day Manager's full-surface **Call Sheet → Edit** (D17) — **the Reports Designer itself in ZONE MODE** (roadmap 212). `ReportDesigner zone={{ designId, blocks, onChange, scope: 'days', previewSectionIndex, showRibbonTimes, renderPage }}` mounts `CallSheetCanvas` through `renderPage`: the host builds the single white page around the editor's BARE canvas node at the design's zone slot. The docked rail (palette ↔ inspector, collapse + `usePaneResize`, persisted prefs), block/column/cell chrome, context menu, keyboard, auto-edit, guards and commit-on-blur are the designer's own — ONE engine, no wrapper (`CallSheetZoneDesigner` retired). The zone is CONTROLLED by the host (`daybreakMeta.callSheets[designId]`): structural edits commit immediately, text commits on blur (251), and a store change under the editor (undo, a peer's save, Reset) re-syncs the local copy behind the pending-text gate. Zone mode is always **Values** (the Fields/Values switch is designer-only, user decision); the toolbar's Times aid is host-owned (page + zone ribbons, `ribbonTimeOverrides`). ONE zone per design: the palette refuses a nested/second zone (`blockAllowedIn` zone rule) and `ReportDesigner.commit` refuses newly introduced duplicates (`countCallSheetZones`); every other zone slot renders the day's content read-only like print. EVERY call-sheet design renders through this same page (`callSheetPageBlocks`: the zone-bearing days repeat's children → a plain days repeat's children → the design body): without a `callSheetEdit` there is no editable zone slot and NO palette — the day page displays display-only instead of a blank canvas (roadmap 211).

  `docs/REPORTS-TOKENS-AND-TABLES.md` — read it before touching
  `reports/CustomTable*.tsx`, `reportTokens.ts`/`reportLookup.ts` or the `@`

- **Inline text editing (roadmaps 191/203)**: a text block edits INLINE on the canvas — `ReportBlockView`'s text case → `InlineTextBlock` (wrapping the app `RichTextEditor` adapter), focused with the caret at the END (kit `focus('end')`, v0.1.93) once token NodeViews render. **Fields mode mounts the live chip editor for EVERY text block** (no entry step; the click that lands in one focuses it — `autoFocus` is Values-only), **Values mounts it on double-click / tap-again** (`editingId` in `ReportDesignerCanvas.tsx`; the Values entry wears the `block-text-editing` outline, Fields editors do not). ONE channel owns it: `ReportDesigner` holds `textEditorRef`/`textRtState`/`textChipKey`, threading them to the canvas (forwarded to the editing block and `BlockChrome`) and `ReportToolbar` (toolbar/dock); `InlineTextBlock` publishes its handle only while the block is SELECTED or FOCUSED (Fields mounts many editors — the dock must target the one being worked on); the chrome's own Content editor is GONE — it renders only the shared `reports/RichTextControls.tsx` body bound to the canvas handle. Leaving the editing block (another selection, background click, Escape) ends editing; in Values the card stays non-draggable while the editor holds focus (drag resumes on blur) so text selection never starts a block drag. Fields keeps the card draggable — the leaf header and padding drag the block, while a `dragstart` inside `.report-text-editor` is cancelled (`ReportDesignerCanvas.tsx`).

- **Fields/Values mode (roadmap 203)**: one global display/edit mode replaces the retired View-menu "Show field keys / Show field values" items. The header's `Fields | Values` kit `Seg` (per-segment `title`, `dense`; sits next to View, works floating + docked) persists `lemon_schedule_report_view_mode` (default **Values**; the old `lemon_schedule_report_keys` key is ignored — no migration). `mode` threads `ReportDesigner` → `ReportDesignerCanvas` → `ReportBlockView`; `showKeys = mode === 'fields'` at that one seam, and the leaf cases branch — text = live editor (Fields) vs resolved + double-click/tap-again entry (Values; an already-selected text block also enters on a single body click, deferred ~250ms so the opening click of a double-click still mounts the editor AFTER the second click — otherwise the second click word-selects inside the just-mounted editor); free table = live cells (Fields) vs static resolved + card-selected resize chrome (Values; entry gestures: `docs/REPORTS-TOKENS-AND-TABLES.md`). **Freshly added text/free-table blocks enter editing with the caret inside** (`autoEditId` set by every insert path and by a table's switch to Free table; the canvas focuses once rendered — free tables get the first cell; Fields mode just focuses the live editor). Preview/print never receive a mode (always values). Text blocks and free tables render the container-style header (`BLOCK_HEADER_CLS`) with a ★ (`src/lib/reportTips.ts` `hasCalculatedContent`; tooltip "Contains calculated values") when their content CALCULATES — text: `{{cellref…}}` or `{{lookup…}}`; free table: cellrefs in cells/header; plain `{{field}}` tokens never star. Attribute (`field`) blocks stay untouched (no header/star).

- **Linked paragraph-style runs (roadmap 193)**: the named-style pick (`TextStyleMenu`) is selection-aware — with a text selection in the focused editor it marks the RUN via the kit's `reportTextStyle` mark (`exec('textStyle', id)`, stored as `<span data-text-style="id">`) and holds a ghost selection while the menu is open; with a collapsed caret it patches the object default (`block.textStyle` / `cellStyles.textStyle`). `resolveReportTextStyleSpans` (`lib/reportTextStyles.ts`) resolves each marker against `project.reportTextStyles` at render time from `resolveReportTokensHtml`, so editing a style restyles every run in canvas, preview and print; a deleted id renders plain. `reports/ReportTextStyleRules.tsx` emits the same typography as scoped CSS for the canvas editors (the mark stores only the link). Applying a run style clears the range's direct font family/size (the object-level precedent); bold/italic marks stay (direct character formatting wins, Word-like).

## Hard-won gotchas

- `aux.index` is 0-based; `counterStart` (block prop) decides where the Counter field starts.
- Nested `elementsOfCategory` repeats render their same-collection tables **once per category** (summary tables — the `onceTables` special case in `ReportRepeatView`, `ReportBlockView.tsx:273`). Don't "fix" this; it's intentional.
- Table axis: `columns` = attributes as columns (one row per item), `rows` = matrix (attributes as rows). `tableItemCollection`/`tableFieldScope` derive the effective collection/field scope — use them, don't inline.
- Pagination (`useReportPaginator` + `lib/reportPagination.ts`): structural pages split at TOP-LEVEL `pageBreak` blocks (`paginateBlocks` — leading no-op, consecutive → blank pages, trailing dropped); no per-item expansion. A `pageBreak` ANYWHERE in the render (repeat/relative children included) is a hard chunk boundary: the block renders an invisible `data-rm-pagebreak` marker, the walker emits a `break` unit and the fill closes the page there — a trailing pageBreak per repeat item gives one page per item. Repeat/relative items DISSOLVE into their children (whole blocks, ribbons by strips, tables by rows with repeated headers, nested repeats recursively — `FragmentPartUnit.itemRange`/`itemParts` carry the path to any depth); items that render nothing produce no pages (a break at a page start is a no-op); unsplittable containers (columns/callSheetEdit) containing a break start on a new page as a whole unit; explicit blank pages survive only from consecutive top-level breaks. Splitting/geometry/budget rules: `docs/REPORT_PRINTING_AND_PAGE_BREAKS.md` §2-3. Design changes → `UPDATE_REPORT_DESIGN` (store `actions/reports.ts`); designs are versioned and trashed like other entities.
- **Per-block item filter (roadmap 100)**: `ReportBlock.itemFilter { field, values }` on repeat/table blocks — `applyItemFilter` (`lib/reportData.ts`) runs beside `filterItemsByScope` in `ReportRepeatView`/`ReportTableView`, so designer, preview and print agree. The block chrome's "Filter rows" control (field picker + values) writes it; a filtered block shows an amber **Filtered** badge in the repeat/table canvas header.
- **Canvas sampling + day picker (roadmaps 197/198)**: a repeat's template preview renders ONE item. Day-scoped designs (`days`/`daysOfCast` repeat or a `callSheetEdit` zone anywhere in the tree — `designIsDayScoped`, `lib/reportBlocks.ts`) get a **View → Report day** submenu (`ReportDesigner.tsx`; options from `useDayViews` — the Day Manager's source, violation counts included), persisted per design (`lemon_schedule_report_preview_day_{designId}`). Two states: **All days** (default; stale stored days fall back here) = canvas samples the FIRST production day of the ACTIVE schedule/calendar and Preview/Print render the WHOLE report (roadmap 197 parity — canvas matches preview/print page 1); **Day N** (pinned — shows as `· Day N` on the View trigger) = the day threads into `sampleRepeatItem` (`lib/reportSampling.ts`; items from `ctx.dayInfos`, never re-derived) AND scopes Preview/Print to it (`dayScopeFilter`, `DayReportPreview.tsx`; the print dialog preselects that day's checklist row — the user can re-check others). ONE day-list body serves both surfaces: `DayPickerList` (`src/components/production/day/DayPicker.tsx`) backs the standalone `DayPicker` dropdown (Days page / Call Sheet edit) and this submenu; its optional `allLabel` row + `selectedIndex` with no matching option = All days, picking it calls `onSelect(-1)`. Other collections pick the first item resolving the most item-scoped tokens (a data-less first row must never show raw `{{tokens}}`). Designer text/free-table editing is mode-gated (roadmap 203 — see the Fields/Values bullet). Day-scoped breakdown tokens (`{{wardrobe}}` …) resolve the same consolidated, de-duplicated day union in text blocks and cells (`dayBreakdownValue`, `reportTokens.ts`).
- **Item lookup tokens / free-table cells** (`#REF!`/`#VALUE!` semantics,
  picker grammar): `docs/REPORTS-TOKENS-AND-TABLES.md`.
- **Skip-empty filter**: `SKIP_EMPTY_TEST`/`SKIP_EMPTY_LABEL` (`lib/reportData.ts`) — per-collection emptiness tests for typed-parent rollups (categories → `elementCount > 0`, locationTypes → `count > 0`; counts built once in `buildReportCtx`). `resolveCollectionItems` applies it when `skipEmptyCategories !== false` (default ON); the repeat/table "Filters" checkbox renders per registered collection ("Skip types with no locations" etc.). A future database registers its test + item count here and both the filter and the chrome follow — no per-collection code.
- Print scoping: `ReportScopeFilter`/`filterItemsByScope` — repeat views MUST apply it after `resolveCollectionItems` (see `ReportRepeatView`). Scopes cover top-level REPEATS only; TABLES always print all items.
- **Context menus (roadmap 219)**: the block/column menu is the kit `ContextMenu` (`reports/ReportContextMenu.tsx`). Pickers are SUBMENUS using the chrome pickers' item bodies: table column + field block → **Attribute** (`FieldPickerItems`), repeat/table → **Repeat over** / **Table over** (`CollectionMenuItems`) — never a forked list (the collection builders `repeatMenuCollections`/`tableMenuCollections`/`collectionPickPatch`/`selfRepeatDisabledCategories` live in `lib/reportBlocks.ts`). "Add block inside" exists ONLY for `repeat`/`relative`, labelled with the EFFECTIVE scope (`insertScope`: a repeat's items / an Advance's parent repeat). Tables are leaves — `insertInto` never descends into one (an insert aimed at a table lands as its sibling; descending created invisible orphans). Impossible actions are `disabled`, not no-ops: Move row/column at the first/last position, Delete row/column with one left (`canMovePrev`/`canMoveNext`/`canDeleteColumn` — the free-table cell menu's `canDeleteRows`/`canDeleteColumns` precedent). `useTableColumnReorder.startDrag` ignores non-left buttons — a right-click's pointerup used to re-select the column, clear `selId` and unmount the open menu. Image ("Remove image") and map ("Use the day's location" / "Clear pin") quick actions patch through `onPatch`; `callSheetEdit` has no Duplicate (hosts honour only the first zone). Free-table cells own their right-click whenever `designer` (`hint` + `onPatchBlock`) — Values-static also opens the cell menu, entering editing at that cell first (`onEnterTableEdit`).
- Empty collections: render `emptyHint` in designer, nothing in print/preview.
- The canvas editor (`ReportDesignerCanvas.tsx`) uses `elementFromPoint` behind a `pointer-events: none` backdrop for right-click targeting — same pattern as the ribbon context menu.
- The block editor panel (`BlockEditorContent`, `blockControls.tsx`) is ONE component rendered on the floating chrome above the block and the docked **inspector rail** (the retired top bar is gone) — any change applies to both. **Docked is the DEFAULT** (`lemon_schedule_report_editor_mode`; floating is opt-in and persists) — the surface switch + collapse live IN the chrome header (block/column/cell chromes; block: `trailing`, column: `headerTrailing`, cell: threaded canvas → `CustomTable` → `CustomCellControls`), so the rail has no separate bar (only the palette state shows a one-row header with the actions). **There is no Deselect button** — Esc / clicking the canvas background deselects. `panel` layout (via `reportEditorLayout.tsx`: `BlockEditorPanelContext`/`useBlockEditorPanel`, `ContentRow` tall wrapper, `editorRowCls`/`editorFieldCls`) stacks labels above controls, fills fields to the column width and wraps rows; the kit `Seg` takes `stretch` there (full-width equal segments) and `EditorCheckbox` makes a checkbox a full-width row (pass `flex-1` in an `EditorGroup` for equal halves — Header row / Cell borders read like the Axis Seg). Group headers use the shared `EditorSection` (panel: eyebrow + hairline rule; bar: label-left row) so **Format/Style/Row/Column read as sections** like Padding/Content; `EditorGroup` keeps related controls (mark buttons, alignment trios, label+input pairs, the checkbox pair) as unbreakable clusters when a row wraps, and cluster dividers are kept on every surface — the kit `FormatToolbar` wraps in place (ui-kit v0.1.96) and `ChromeHeader` wraps both its trailing slot and the trailing's own contents (v0.1.98; `StructureControls` stays one cluster). **Nothing clips**: never force `min-w-max` on the rail, and never reserve an empty grid column (a text block has no Style column — Padding gets the full width). Sections stack: **Style** and **Padding** side by side (two columns) → **Outline** (background fill + border toggle — `field` blocks only) → content groups in reading order — repeat/table: **Display** (Mode · Axis · header/borders · day format) → **over** → **Filters** → **Behavior**; text: **Format** → **Style**. Palette attributes are `type: 'text'` blocks carrying a `{{field}}` token (never `type: 'field'`), so the text-block controls ARE the attribute-block controls — inserted from the editor's own `@` picker (the old separate "Insert attribute…" control is gone, roadmap 205). ## Printing flow (custom reports)

Print NEVER fires directly — every entry point opens `ReportPrintDialog`
(`components/reports/ReportPrintDialog.tsx`) first: designer toolbar Print
(`ReportDesigner.tsx:351`) and File → Print → Custom Reports
(`onPrintReport` in `AppHeader.tsx`) call `setCustomReportPrint(design)` in `App.tsx`.
The dialog calls `onPrint(scopes, printOptions)` → `handleReportPrint`
(`App.tsx:624`) → `ReportPrint` renders via the measured paginator; it
signals `onReady` and only then `window.print()` fires.

### Dialog invariants (MUST NOT)

1. **Never print without the dialog** — `handleReportPrint(design)` called
   straight from a button was the direct-print bug (main-window DesignTab);
   every entry point goes via `setCustomReportPrint`.
2. **Scopes cover top-level REPEATS only** — `scopeFor` in
   `ReportPrintDialog.tsx` matches `block.type === 'repeat'`; TABLES always
   print all items — never add table controls to the dialog.
3. **Ribbon overrides are print-only** — `RibbonPrintOptions`/`ReportPrintOptions`
   (`reportData.ts:123`) never mutate the `ReportDesign`. Keyed by block id,
   they apply to every ribbon block anywhere in the design (nested in repeats/
   columns/header/footer — `collectRibbonBlocks`).
4. **Ribbon defaults come from the block's own props every time the dialog
   opens** — ribbon settings are never persisted; only `page` persists
   (`lemon_schedule_report_print_page_{projectId}`).
5. **Overrides flow through `ReportRibbonView`'s `overrides` prop**
   (`ReportRibbonView.tsx:544`) and replace the block's flags entirely when
   present. The modal preview is `RibbonDummyPreview` (`ReportRibbonView.tsx:635`)
   — dummy daybreak + strips + note/break rows rendered with the REAL row
   renderers and the override flags, so every toggle is visible.
