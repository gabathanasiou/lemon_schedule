# Roadmap Item 25 — Repeater/table "over" menus: hide self-redundant collections

## What changed

- `src/lib/reportBlocks.ts` — added `isSelfRepeat(parent, collection, parentCategory, category)`, the single source of truth for self-redundant nested collections: `days` under day-item parents (`days`, `daysOfCast`), `scenes` under scene-item parents (`scenes`, `scenesOfDay`, `scenesOfElement`, `scenesOfCast`), `crew` under `crew`, plus the grayed self-category cases for the Elements submenu (`elements`/`elementsOfCategory` parents → parent's own category; `cast`/`scenesOfCast` parents → category `cast`). `categories` under `categories` and `violationTypes` under `violationTypes` are intentionally kept. Also made `scopedCollectionLabel` return the plain label for `crew` parents (no "(of this crew member)" decoration — crew is non-rule-bearing).
- `src/components/reports/CollectionMenu.tsx` — gained `disabledCategories?: string[]` prop; Elements-submenu categories in that list render `disabled` (grayed). The current value is always exempted from the gray-out inside the menu (`value === 'elements' && category === key` stays enabled), so existing designs stay editable.
- `src/components/reports/blockControls.tsx` — both menu call sites now filter by `isSelfRepeat`:
  - Repeat "Repeat over" menu: new `repeatMenuCollections()` helper lists contextual variants first, then base collections minus `isSelfRepeat` picks, ALWAYS re-including the block's own effective collection (`block.collection || 'scenes'`, except `cast` which is reached via the Elements submenu).
  - `NestedTableMenu` ("Table over"): base-collection loop now skips `isSelfRepeat` picks; the `preserved` explicit-collection logic already keeps the current value. Receives `parentCategory` now.
  - Both menus pass `disabledCategories` (self-category per parent) into `CollectionMenu`.
  - The "Only … in this …" scope checkbox is hidden when the immediate parent is `crew` (crew scoping is a no-op — honest until item 11 makes crew rule-bearing).
- `e2e/report-menu-self-repeat.spec.ts` — new Playwright spec: 5 tests covering the days/scenes/crew hide cases for repeats AND tables, the current-value exemption (fresh child over Scenes under a Scenes parent keeps 'Scenes' listed until switched away), crew honest labels (no "(of this crew member)", no "Only … in this crew member" checkbox), and the Elements-submenu gray-out under a Cast parent (Cast grayed, Props not).

## Invariants touched

- **Collection menus** (`REPORTS-DESIGNER.md` "Extending" recipe: picker lists come from `blockControls.tsx`/`CollectionMenu.tsx`): the nested menu lists now pass through `isSelfRepeat` — new collections added to `ReportCollection`/`COLLECTION_ORDER` need a corresponding rule in `isSelfRepeat` if they self-repeat.
- **LEGO scoping** (`REPORTS-LEGO-CONTEXT.md` §2): crew ancestors are non-rule-bearing (`ruleBearingAncestor`, `reportData.ts:620`). The crew interim (no "(of this crew member)" decoration, no scope checkbox under crew parents) is now enforced in the UI to match the already-correct data-layer behavior. Removed when item 11 lands.
- **No migration**: self-repeat collections already stored on blocks keep rendering; the menus always re-expose the block's current value.
- The top-level (non-nested) table menu at `blockControls.tsx` is untouched (`parentCollection` undefined → `isSelfRepeat` returns false) — top-level designs are unaffected.

## Assumptions

- `elementsOfCategory` parents: the parent's own category is dynamic (per parent item) and not statically available in the menu; the gray-out fires only when a static `parentCategory` exists (e.g. `elements` parents, or an outer `elements`/`cast` context inherited via `parentCategoryOf`). No false positives are introduced.
- The roadmap's "gray out … under element/cast-item parents" is implemented as disabled (non-clickable, `opacity-30`) Elements-submenu items, with the current value exempted — matching "ALWAYS exempting the current value so existing designs stay editable".
- Crew interim implemented as: decoration + scope checkbox suppressed when the **immediate** parent collection is `crew` (deeper nesting like `crew → days → scenes` still references the rule-bearing day, which is honest).
- Port collision: another feature worker's Vite server occupies port 3001 (config has `reuseExistingServer: true`). All my Playwright runs used a throwaway config on port 3002 with `sed`-patched spec copies; the committed spec uses the standard helpers (port 3001).
