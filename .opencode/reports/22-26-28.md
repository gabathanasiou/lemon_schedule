# Roadmap Items 22 + 26 + 28 — Day-repeater Breakdown fields, block gap, text/field border+background

Grouped into one worker because they share files (`types.ts`, `reportStyle.ts`, `ReportBlockView.tsx`, `blockControls.tsx`). Three focused commits + one test commit, in this order: 22 → 26 → 28 → spec.

## What changed

### Item 22 — Breakdown attributes pickable + resolving inside day repeaters
- `src/lib/reportFields.ts`:
  - `fieldsForScope` now includes the `Breakdown` group for day scopes (`days`, `daysOfCast`) — the ONLY scene-scope fields admitted into a day context (Scene Info/Shooting fields stay scene-only).
  - New `dayBreakdownValue(ctx, def, day, scope)` — the union of that day's scenes' values (distinct cast working that day, distinct props/categories across the day's scenes), deduped case-insensitively, composed with the ancestor `sceneScope` intersection like the smart fields. Field extraction stays in the registry (`def.get` per scene — never re-derived).
  - `fieldValueSafe` routes scene-scope `Breakdown` fields to `dayBreakdownValue` when the item is a day (`typeof item.section?.index === 'number'`). Single choke point — covers text tokens (`resolveToken`), field blocks, table cells (`reportFieldValueByKey`) everywhere (canvas/preview/print). Legacy scene-only tokens (`{{sceneNumber}}`) inside day repeaters keep rendering '' (unchanged).
- Picker plumbing needed no per-call-site changes: palette, field-block chrome, table columns and the text-editor `@` autocomplete all flow through `fieldsForScope`.

### Item 26 — Block gap: default 10px vertical spacing between blocks
- `src/types.ts` — `ReportBlock.blockGap?: number`.
- `src/components/reports/reportStyle.ts` — `DEFAULT_BLOCK_GAP = 10` + `blockGapMargin(b, isFirst)` (first-in-stack and `pageBreak` blocks get 0).
- `src/components/reports/ReportDesignerCanvas.tsx` — `renderBlocks` card wrapper (`<div key={b.id}>`) gets `marginTop: blockGapMargin(b, i === 0)` — covers body, header/footer zones, repeat children and column stacks (all recursive renderBlocks calls).
- `src/components/reports/useReportPaginator.tsx`:
  - `wholeUnit` reads the wrapper's computed `marginTop` into `gapBefore`; new `blockGapBefore(wrapper, fragChild)` applies the same to the FIRST unit of splittable blocks (`flattenRepeat`, `flattenTable` — on the header unit or first row — and the ribbon flatten), so budgets include the spacing everywhere. Fragment-internal calls (`fragChild` set) skip it — those margins live inside the item and are covered by its `offsetHeight` (roadmap: "no change" for fragments).
  - `ReportMeasureContainer` `.rm-block` wrappers (body + header/footer zones) get the margin; fragment wrappers use their repeat block's own gap.
- `src/components/reports/ReportBlockView.tsx` — chunk-page body mounts (all six `BodyChunk` kinds) + header/footer mounts get `marginTop` (first-child CSS zeroes page tops); `ReportRepeatView` children and once-tables wrap with the margin; `FragmentBody` `.rm-frag-child` gets it; columns: hardcoded `gap: 8` replaced by per-child margins (outer horizontal `gap: 12` stays); the unused structural twin `ReportPageItems` got the same treatment.
- `src/index.css` — `.rm-body > :first-child, .report-page-content > :first-child { margin-top: 0 !important; }` keeps page tops clean in the measure pass and the rendered pages (print + preview).
- `src/components/reports/blockControls.tsx` — universal "Gap (px)" number input (every block type except `pageBreak`) in a Layout section, mirroring the repeat's "Item gap (px)" row.

### Item 28 — Text/field blocks: border + background with auto text color
- `src/lib/reportLook.ts` (new shared module) — `REPORT_BORDER_COLOR` (#d4d4d8), `REPORT_TABLE_HEADER_BG` (#f4f4f5), `getReportBorder(showBorders)`, `relativeLuminance(hex)` (sRGB linearized) and `autoTextColor(background)` (white below ~WCAG midpoint luminance, black otherwise). Consumed by table cells AND text blocks — one place for future table-look changes.
- `src/types.ts` — `ReportBlock.background?: string` + `border?: boolean`.
- `src/components/reports/reportStyle.ts` — `getReportBlockBaseStyle` uses `autoTextColor(b.background)` instead of hardcoded `color: '#000'`, plus background fill and the 1px border when set.
- `src/components/reports/ReportBlockView.tsx` — table border via `getReportBorder(block.showBorders !== false)`; table header/label backgrounds via `REPORT_TABLE_HEADER_BG` (2 sites).
- `src/components/reports/blockControls.tsx` — StyleControls gains a "Background" `ColorField` (+ small ✕ to remove) and a Border toggle, for text/field blocks only (`block.type !== 'link'`). Named text styles stay typography-only (applying a style does not clear background/border).

## Invariants touched

- **Field registry single-source** (`docs/REPORTS-DESIGNER.md` pillar 3): no new fields were added — Breakdown fields stay `scope: 'scenes'`; the day-context inclusion is an explicit `fieldsForScope` rule (`days`/`daysOfCast` → `Breakdown` group), and the per-day resolution lives in `fieldValueSafe`/`dayBreakdownValue`, NOT in a parallel registry or view logic.
- **LEGO scoping**: `dayBreakdownValue` composes with `aux.sceneScope` (the `ancestorSceneScope` intersection) exactly like `smartScenesOf` — a days repeater nested in a cast/element chain only unions the surviving scenes.
- **Canvas = preview = print** (`docs/REPORT_PRINTING_AND_PAGE_BREAKS.md` rule 8): the block gap is applied by the canvas card wrappers, the measure-container `.rm-block` wrappers and the chunk-page mounts from the same `blockGapMargin` helper; page budgets include the spacing (`wholeUnit`/`blockGapBefore` gapBefore reads). `report-pagination.spec.ts` (budget assertion) passes on Desktop Chrome AND iPad WebKit.
- **Pagination chunk granularity**: no new chunk kinds; whole blocks move whole (wholeUnit now carries the margin), splittable blocks budget their margin before their first unit.
- **ReportBlock is the single block model** — new props are optional; no migration, no store/action changes.

## Assumptions

- **Spacer blocks get the default gap** like every other block (only `pageBreak` is excluded). The roadmap's "spacer blocks remain for exact manual spacing" was read as "spacers still exist for manual spacing" — exact spacing is achieved by setting that block's Gap to 0 in the new input. If the user intended spacers to be gap-exempt, the fix is one condition in `blockGapMargin`.
- **Fragment children** (`.rm-frag-child`) render with the block gap, but the paginator does NOT budget inter-fragment margins (roadmap: "no change" — they live inside the per-item page and its `offsetHeight`). Per-item pages are typically small; the conservative `contentHeight` absorbs the slack.
- **Header/footer zones** get the gap too (first block flush) so the canvas and print/preview match rule 8, even though the roadmap's print/preview list only named the body wrappers.
- `dayBreakdownValue` dedupes cast by resolved NAME (not ID) — two cast members with identical names merge. Matches the existing `distinctElementsIn` precedent; rare in practice.
- Auto text color threshold: `relativeLuminance >= 0.2` → black text (≈ WCAG midpoint). Unparseable background values count as light (black text).
- The canvas `firstItemOf` sampling is unchanged — a days repeat samples the first day that resolves all item tokens (day 2 in the seeded project, since day 1 has no props) — verified by the e2e spec rather than assumed.
