# Roadmap 23 + 24 — Table resize fix + shared column-resize dragger

Items 23 and 24 implemented as ONE unit (item 24's shared dragger swap
supersedes 23 — it fixes the resize bug; verified together).

## What changed

- **`src/components/columnResize.tsx`** (new) — the shared column-resize
  dragger, extracted from the ribbon designer's gold-standard `startResize`:
  - `useColumnResize(widths, { apply, commit, getWidth, touchActionTargets, minPct })`
    — one pointer session: `setPointerCapture`, `touch-action: none` locking
    (targets + `document.body`), document-level move/up (via
    `useCurrentDocument` so popout windows work), MIN_PCT (2.5) clamps on the
    dragged pair, Shift = scale all right columns, commit on release with the
    final widths. Math copied verbatim from the ribbon (`RibbonTab`).
  - `ColumnResizeStrip` — handle strip: a grid mirroring the column widths with
    a handle at each cell's right edge; `variant="tab"` (ribbon triangles,
    coarse-pointer sizing) or `variant="bar"` (table's slim blue bars).
    Consumers live-track handles by writing `gridTemplateColumns` to the
    strip's container (`containerRef`) — the ribbon's existing mechanism.
- **`src/components/RibbonTab.tsx`** — the inline `startResize` (pointer
  session + clamp math, ~70 lines) replaced with `useColumnResize`; the apply
  callback keeps the exact live-CSS behavior (grid + tab bar + previews). The
  dead `MIN_PCT` import dropped; `currentDocumentRef` kept (still used by the
  keyboard listener).
- **`src/components/ribbon/RibbonDesignerGrid.tsx`** — the tab bar's grid
  markup swapped for `<ColumnResizeStrip variant="tab" …>`; visuals and the
  coarse-pointer variants are byte-identical.
- **`src/components/reports/ReportDesignerCanvas.tsx`**:
  - `TableResizeBar` rewritten on the shared dragger. Widths now apply by
    column **index** (`data-table-col-ci`) — no more `columns.findIndex(c =>
    c.id === …)` id-lookup — to header AND every body cell, so all rows track
    the drag live. **The commit no longer clears the live inline widths**: the
    old clear-then-patch pattern left unchanged columns (e.g. `7% → 7%`)
    without an inline width after React's style diff skipped them, so the flex
    row re-distributed and the whole table shifted — the actual item-23 bug.
    Live handle tracking added (strip `gridTemplateColumns`), plus pointer
    capture + touch locking (iPad/pencil-ready).
  - Columns-block gutter resize deduped onto `useColumnResize` (inside
    `GutterZone`, which owns the hook per gutter) — third copy of the same
    logic removed; its commit also no longer clears the live `flex` styles
    (same React-style-diff trap).

## Assumptions (judgment calls)

- **Shared component shape**: a hook (`useColumnResize`) + a presentational
  strip (`ColumnResizeStrip`) with two handle variants ('tab'/'bar'). The
  ribbon's grid tab-bar markup was preserved as the strip's grid mechanism so
  live drag tracking and visuals stay identical; only the behavior/pointer
  session is shared. The strip is a grid (same template as the columns) so
  consumers live-track handles with the existing `gridTemplateColumns` write.
- **Columns-block gutter converted too** — the roadmap says the dragger "also
  benefits the columns-block gutter resize"; it was the third copy of the same
  logic, so it was deduped onto the hook. Its commit also stops clearing the
  live `flex` styles (same style-diff trap as the table bug).
- **Shift = scale-right applies to the table/columns resizes too** — the
  ribbon behavior becomes the single standard; superset of the old behavior.
- **Table clamps lowered 5 → 2.5 (MIN_PCT)** — ribbon standard.
- **Table spec seeds its design pre-boot** (report-pagination pattern) instead
  of relying on the app's default design — the debounced save raced the
  localStorage read.
- **Dev-server staleness in this worktree**: `DISABLE_HMR` disables Vite's
  watcher, and a leftover `vite` child can survive playwright's server
  teardown and be reused with stale module transforms. All verification above
  was run against a freshly killed port.
